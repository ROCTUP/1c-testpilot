# Повторный заказ клиента в демобазе УТ

Рабочий пример полноценного пользовательского сценария на pytest:
[test_repeat_order.py](test_repeat_order.py).

Клиент «Протон» повторяет заказ. Менеджер копирует прежний документ, указывает номер
заявки клиента и комментарий, увеличивает количество товаров, проверяет сумму и
сохраняет новый заказ. Затем открывает его заново и проверяет сохранённые данные.

## Что делает тест

1. Открывает список заказов и находит **ТД00-000001 от 06.04.2022**, клиент **Протон**.
   Проверяет организацию, товары, количества, цены и исходный итог **42 000 руб.**
2. Создаёт копию штатной кнопкой списка. Одним `set_fields` заполняет номер по данным
   клиента и уникальный комментарий вида `Testpilot pytest 20260918-...`.
3. Сохраняет снимок формы с таблицей. Меняет количество в первой строке с 2 на 3,
   во второй — с 1 на 2 через `set_row_values`. Проверяет изменения таблицы в снимке.
4. Проверяет обе строки и итог формы:

   | Строка | Товар | Количество | Цена | Сумма с НДС |
   |---|---|---:|---:|---:|
   | 1 | Телевизор "SHARP" | 3 | 14 000 | 42 000 |
   | 2 | Телевизор "SHARP" | 2 | 14 000 | 28 000 |
   | | **Итого** | **5** | | **70 000** |

   В исходном демозаказе этот товар уже находится в двух строках. Тест сохраняет
   структуру заказа и цены, в которые включён НДС.
5. Нажимает **«Записать»**, проверяет отсутствие несохранённых изменений и получение
   навигационной ссылки на новый документ. Закрывает карточку.
6. Открывает сохранённый заказ по полученной ссылке. Повторно проверяет клиента,
   организацию, номер заявки, комментарий, товарные строки и итог **70 000 руб.**
7. Заново открывает исходный заказ и сравнивает его реквизиты, строки и итог
   с прочитанными в начале. Исходный заказ не редактируется.

Новый заказ **остаётся в базе для просмотра**. Каждый запуск создаёт новый документ
с собственным номером и уникальным комментарием; тест не проводит его и не удаляет.
Запущенный тестом клиент 1С завершается fixture после теста, в том числе при ошибке.

## Запуск

Пример проверяется на демобазе **УТ 11.5.27.88**, платформа **8.3.27.1936**, Windows.
В базе должны сохраниться исходный демозаказ и его данные. Если их изменили или скрыли
отбором списка, тест завершится с ошибкой проверки исходных условий.

Из корня репозитория установите пакет с поддержкой pytest:

```powershell
python -m pip install ".[test]"
```

Проверьте путь к базе и платформе в [profiles.yaml](profiles.yaml). В примере
используется пользователь `Администратор` без пароля и изолированный рабочий стол.

```powershell
$env:TC1C_PROFILES_FILE = (Resolve-Path "examples/pytest/ut/profiles.yaml").Path
$env:TC1C_SCREENSHOTS = "false"
$env:TC1C_LOGGING = "true"

python -m pytest examples/pytest/ut/test_repeat_order.py --tc-profile ut_demo --tc-artifacts test-results/ut --junitxml test-results/ut.xml -v -s
```

Для запуска из исходников без установки добавьте `app` в `PYTHONPATH` и передайте
pytest параметр `-p testpilot_pytest`, как описано в [Python API](../../../docs/PYTHON_TESTING.md).

## Что видно после запуска

В консоли выводятся шесть этапов, результат pytest, номер нового заказа и его
уникальный комментарий. В отдельном каталоге теста находятся:

- `created-order.json` — номер в заголовке, ссылка на документ и тестовая пометка;
- `source-before.json`, `source-after.json` — проверка исходного заказа;
- `order-before-save.json`, `order-reopened.json` — данные до записи и после открытия;
- `snapshot.json`, `changes.json` — снимок и изменения формы с таблицей;
- `save-response.json` — результат нажатия «Записать» с диагностикой;
- `result.json` и каталог журнала `session-*` с HTML-отчётом;
- при ошибке — `context.json`, если контекст удалось прочитать.

Снимок здесь дополняет конкретные проверки. В этой форме отдельные информационные
поля могут не возвращать представление: это отражается в `errors` и `complete=false`.
Тест отдельно требует успешного чтения таблицы снимка и проверяет ожидаемые значения
полей, обеих строк и итога; неполный снимок не считается доказательством их корректности.

Все действия выполняются через публичный Python API и протокол клиента тестирования.
MCP-сервер, расширения конфигурации и выполнение встроенного кода 1С для теста не нужны.
Адреса элементов и ссылка на новый документ получаются заново при каждом запуске.
