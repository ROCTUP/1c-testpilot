# Приём нового сотрудника в демобазе ЗУП

[test_hire_employee.py](test_hire_employee.py) — полный пользовательский сценарий:
кадровик заводит физическое лицо, создаёт для него сотрудника и проводит приём
с назначением оклада **45 000 рублей**. Затем тест открывает сохранённые данные
и проверяет результат приёма в карточке сотрудника.

## Результат прогона

[HTML-отчёт со скриншотами](result/report.html) — последний успешный прогон этого
примера. В папке `result` сохранены журнал вызовов, **69 скриншотов**, результат
pytest и JSON-файлы с проверенными данными физлица, сотрудника и приёма.

Откройте `result/report.html` в браузере. Для просмотра достаточно файлов примера;
запускать 1С не требуется. При копировании отчёта сохраните рядом папку `screenshots`.

## Этапы и проверки

1. Создать физлицо с уникальной фамилией `Тестпилотов…`, именем Алексей,
   отчеством Сценариевич, датой рождения 17.04.1990 и полом «Мужской».
   Записать, закрыть, открыть заново и проверить эти данные.
2. Из карточки физлица нажать **«Новое место работы»** и создать связанного
   сотрудника организации **Крон-Ц**. Из его карточки открыть приём на работу.
3. Заполнить приём:

   | Реквизит | Значение |
   |---|---|
   | Дата документа и приёма | 01.10.2021 |
   | Подразделение | Отдел по работе с персоналом |
   | Должность | Начальник отдела |
   | Занятость | Основное место работы, 1 ставка |
   | График | Пятидневка |
   | Испытательный срок | 3 месяца |
   | Начисление | Оплата по окладу |
   | Оклад и ФОТ | 45 000 рублей |

4. Создать отдельную тестовую трудовую функцию и выбрать её в приёме.
   Код ОКЗ **1212 — «Управляющие трудовыми ресурсами»** выбирается из встроенного
   классификатора через его группы. В исходной демобазе подходящей функции нет;
   это подготовка обязательного реквизита документа через обычный интерфейс.
5. На странице «Оплата труда» изменить показатель **«Оклад»** в таблице начислений
   через `set_row_values`. Проверить название начисления, показатель, значение,
   вклад в ФОТ и общий ФОТ. Остальные реквизиты проверяются групповым чтением полей.
6. Нажать **«Провести»**, закрыть документ и открыть его по навигационной ссылке.
   Проверить номер, сохранённые реквизиты и строку начисления.
7. Повторно открыть сотрудника и проверить дату приёма, подразделение, должность,
   график, занятость, ставку, оклад и ФОТ. Эти сведения подтверждают результат
   проведения; успешного ответа на нажатие кнопки для прохождения теста недостаточно.

Месячный расчёт зарплаты в этот сценарий не входит: оклад назначается при приёме.
Дата 01.10.2021 выбрана для периода данных демобазы. Тест рассчитан на сохранённые
в ней организацию, подразделение, штатную позицию и график. Изменённые исходные
условия должны приводить к явному отказу проверки.

Каждый запуск **оставляет в базе** физлицо, сотрудника, трудовую функцию и проведённый
документ. Фамилия и название функции уникальны, в комментарии приёма стоит
`Testpilot pytest — приём …`. Используйте демобазу: проведение изменяет кадровые
данные. Фикстура завершает запущенный ею клиент и при успешном тесте, и при ошибке;
созданные данные не откатывает.

## Запуск

Пример рассчитан на **ЗУП 3.1.35.13**, платформу **8.3.27.1936**, Windows.
Проверьте пути к базе и платформе в [profiles.yaml](profiles.yaml).
Профиль использует `Администратор` без пароля и изолированный рабочий стол.

Из корня проекта:

```powershell
python -m pip install ".[test]"

$env:TC1C_PROFILES_FILE = (Resolve-Path "examples/pytest/zup/profiles.yaml").Path
$env:TC1C_SCREENSHOTS = "false"
$env:TC1C_LOGGING = "true"

python -m pytest examples/pytest/zup/test_hire_employee.py --tc-profile zup_demo --tc-artifacts test-results/zup --junitxml test-results/zup.xml -v -s
```

Плагин pytest подключается при установке пакета. Запуск из исходников без установки
описан в [документации Python API](../../../docs/PYTHON_TESTING.md).

В консоли видны этапы, результат pytest, ФИО и номер нового приёма. В каталоге теста:

- `created.json` — ФИО, тестовая пометка и ссылки на созданные объекты;
- `person-reopened.json` — проверка записанного физлица;
- `hiring-before-post.json`, `hiring-reopened.json` — данные приёма;
- `post-response.json` — ответ на проведение с диагностикой;
- `employee-after-hiring.json` — проверенные результаты приёма;
- `result.json` и журнал вызовов с HTML-отчётом;
- при ошибке — `context.json`, если удалось прочитать контекст формы.

Тест работает через публичный Python API и клиент тестирования 1С, без MCP-сервера,
расширений конфигурации и выполнения встроенного кода 1С. Скриншоты отключены.
