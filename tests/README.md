# Тесты транспорта без 1С

Из корня репозитория:

```sh
PYTHONPATH=app python -m unittest discover -s tests -v
```

PowerShell:

```powershell
$env:PYTHONPATH = "app"
python -m unittest discover -s tests -v
```

Используются `unittest` и локальные `socket.socketpair()`. На Linux дополнительные
пакеты не нужны. На Windows импорт `tc1c` требует `pywin32`, штатную зависимость
проекта. MCP-сервер и платформа 1С не запускаются, информационная база не нужна.

Проверки:

- Регрессия #8: GUID в дескрипторах `c0 55` и `e0 55` содержит байты, похожие
  на тег и длину строки. Они не должны превращаться в ожидание лишних данных.
- Каждый вариант разбиения короткого кадра на два чтения, побайтовое чтение,
  несколько кадров в одном потоке.
- Экранированные трейлер и escape-маркер внутри данных, включая границы escape.
- Строки длиннее 65 535 единиц, восьмибайтовая длина, UTF-16 с суррогатной парой.
- Таймаут посреди ответа: сохранение буфера, дочитывание запоздавшего ответа,
  однократный callback и получение именно ответа на новую команду.
- Если запоздавшего ответа нет, следующая команда не отправляется.
- EOF посреди кадра закрывает соединение и запрещает повторную отправку.

Кадры синтетические, это не записи обмена с платформой. Тесты закрепляют контракт
транспортного слоя `TestClient`, включая путь `send_cmd`, но не проверяют
рукопожатие, полный формат ответа `GetCurrentErrorInfo`, MCP-диспетчер или работу
настоящего клиента 1С. Разбиение чтений задаётся обёрткой сокета, поэтому не зависит
от того, как ОС объединит отправленные данные. Единственные короткие ожидания
относятся к проверкам настоящего таймаута; синхронизация потоков не использует sleep.
