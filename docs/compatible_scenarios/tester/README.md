# Совместимые сценарии Тестера

`tc_run_compatible_scenario` и `client.run_compatible_scenario()` запускают
поддерживаемые BSL-сценарии [Тестера](https://github.com/grumagargler/tester) через уже подключённый клиент 1С.
Отдельный менеджер тестирования не нужен. Обработка Testpilot.epf требуется
только для автоматического заполнения `Мета` / `Meta` из подключённой базы.

Это исполнитель части языка и API Тестера. Перед переносом готовых тестов
проверьте [ограничения совместимости](#ограничения-совместимости): они касаются
как отдельных команд, так и вариантов использования уже поддержанных функций.

## Включение MCP

```dotenv
TC1C_COMPATIBLE_SCENARIOS=true
```

По умолчанию инструмент отсутствует в MCP. Флаг управляет только публикацией
инструмента; Python API доступен независимо от него.

## Python и pytest

```python
from testpilot import Client

with Client(profile='demo') as client:
    result = client.run_compatible_scenario(
        path='examples/compatible_scenarios/tester/ПроверитьСписок.bsl',
        parameters={
            'Ссылка': 'e1cib/list/Справочник.Контрагенты',
            'Таблица': 'Список',
            'Повторы': 3,
            'МинимумСтрок': 1,
        },
        timeout=1800,
    )
    assert result['result']['Количество'] >= 1
```

В pytest тот же метод вызывается у клиента из фикстуры `testpilot`.
В MCP инструмент `tc_run_compatible_scenario` принимает те же параметры и
`connection_id` для выбора подключения.

Пути относятся к компьютеру, где запущен Testpilot. `roots` задаёт корни сценариев
и библиотек, например `['/tests', '/libraries/CommonTests']`. Если его опустить,
используется каталог запускаемого файла. Файлы — UTF-8.
`framework` пока принимает только `tester`.
`application_name` задаёт `AppName`/`ИмяПриложения`, если библиотека выбирает
настройки по имени приложения Тестера. Подключение этот параметр не меняет.
`environments_path` — необязательный путь к SQLite-файлу сведений об окружениях.
С ним `СохранитьОкружение` сохраняет записи между запусками; без него они остаются
в памяти. Подробнее — в разделе [Сведения о тестовых окружениях](#сведения-о-тестовых-окружениях).
`parameters` может быть структурой, массивом, строкой, числом или булевым значением.

Пример меняет текущую строку и выделение таблицы. Перед запуском укажите ссылку
и имя таблицы своей конфигурации.

## Библиотеки разных приложений

Третий аргумент `Вызвать` / `Call` и `Позвать` / `Run` выбирает приложение,
которому принадлежит вызываемый сценарий. Сопоставьте имена приложений Тестера
с каталогами их выгруженных библиотек:

```python
client.run_compatible_scenario(
    path='/tests/УТ/Продажа.bsl',
    application_name='УТ',
    roots=['/tests/УТ', '/tests/ОбщиеБиблиотеки'],
    applications={'ERP': ['/tests/ERP'], 'ЗУП': ['/tests/ЗУП']},
)
```

Тогда существующий вызов `Вызвать("Общее.Проверить", ПараметрыПроверки, "ERP")`
найдёт `/tests/ERP/Общее/Проверить.bsl`. Поддерживаются и обычные расширения
выгрузки Тестера `.1c.bsl` / `.1cm.bsl`. Подключение к клиенту 1С остаётся прежним.

Вложенный `Вызвать` без третьего аргумента сначала ищет библиотеку приложения
вызывающего файла, затем — в `roots`. Явное имя ограничивает поиск каталогами
этого приложения; для текущего `application_name` без отдельного сопоставления
используются `roots`. Имена приложений сравниваются без учёта регистра.
У `Позвать` путь дополняется папкой вызывающего сценария, в том числе при выборе
другого приложения. При возврате из вызова поиск снова выполняется относительно
вызывающего файла. `AppName` / `ИмяПриложения` сохраняет значение запуска.

Неизвестное приложение даёт `scenario_application_missing`. Статические имена
и их зависимости проверяются до выполнения; вычисляемые имена — при вызове.
Каталоги разных приложений не должны пересекаться.

## Метаданные в сценарии

`Мета` и `Meta` дают одну структуру в формате штатной `Meta.epf` Тестера:

```bsl
Товар = Мета.Справочники.Номенклатура;
Сообщить(Товар.Synonym);
Сообщить(Товар.Forms.ФормаСписка.Name);
```

Имена объектов и форм в примере замените именами своей конфигурации.
Поддержаны коллекции справочников, документов, регистров сведений,
бизнес-процессов и задач. У объекта доступны `Type`, `Name`, `Synonym`,
`ListPresentation`, `ExtendedListPresentation`, `DefaultListForm`, `Forms`;
у формы — `Name` и `Synonym`. Если основная форма списка не назначена,
`DefaultListForm` равна `Неопределено`.

При первом обращении к переменной данные читаются из подключённой базы через
Testpilot.epf в привилегированном режиме и сохраняются до конца текущего теста.
Повторные обращения и вложенные сценарии используют эту же структуру.
После `Подключить` к другому клиенту читаются его метаданные. Сценарии без
обращений к `Мета` не вызывают обработку; `check_only` тоже её не вызывает.
Нужна актуальная Testpilot.epf, открытая при запуске клиента через `code_epf`.

Как в Тестере, язык имён коллекций зависит от языка пользователя 1С:
`Справочники` / `Catalogs`, `Документы` / `Documents`,
`РегистрыСведений` / `InformationRegisters`, `БизнесПроцессы` / `BusinessProcesses`,
`Задачи` / `Tasks`. Имена свойств (`Synonym` и другие) всегда английские.

Если уже есть JSON из `Meta.epf` Тестера, передайте
`metadata_path='/tests/metadata.json'` в `run_compatible_scenario`.
В этом случае используется файл, обработка не требуется. Он применяется ко всем
подключениям этого запуска; за соответствие файла тестируемой базе отвечает
выбор файла при запуске. В наборе тестов каждый тест получает свою структуру.

## Набор тестов

В том же `path` можно передать каталог или упорядоченный список файлов:

```python
# Найти сценарии в каталоге и его подкаталогах.
result = client.run_compatible_scenario(path='/tests/Продажи', timeout=3600)

# Выполнить в заданном порядке. Повтор файла означает повторный запуск.
result = client.run_compatible_scenario(
    path=['/tests/СоздатьЗаказ.bsl', '/tests/ПроверитьЗаказ.bsl'],
    roots=['/tests', '/libraries/CommonTests'],
    stop_on_failure=True,
)
```

При сборе каталога выбираются файлы с `"Type": "Scenario"` в соседнем JSON-файле
Тестера; помеченные `"DeletionMark": true` исключаются. Для старой выгрузки без
JSON сценарии определяются по расширению `.1c.bsl`. Методы `.1cm.bsl`, библиотеки,
пустые старые контейнеры и обычные `.bsl` без указанного типа не становятся
самостоятельными тестами. Они могут использоваться как зависимости сценариев.
Для собственного `.bsl` достаточно соседнего файла с тем же именем и расширением
`.json`, содержащего `{"Type": "Scenario"}`. В явном списке такая отметка не нужна.

Каталог упорядочивается по полному логическому пути сценария без учёта регистра.
Файл `Продажи/Продажи.dir.bsl` соответствует пути `Продажи`. Это соответствует
принципу сбора задания Тестера по `Scenarios.Path`; точная сортировка его базы
может отличаться для отдельных символов. Явный список задаёт порядок без сортировки,
как строки уже составленного задания Тестера.

Перед первым действием проверяются все тесты и их статические зависимости.
Если проверка не прошла, весь набор остаётся невыполненным. `check_only=True`
возвращает эту проверку без подключения к 1С. После начала выполнения обычная
ошибка одного теста по умолчанию не мешает следующим; `stop_on_failure=True`
останавливает набор на первой ошибке. Общий таймаут, аварийный обрыв соединения или
недочитанный ответ останавливают дальнейшее выполнение.

Намеренное `Отключить()` не останавливает набор. Следующий тест может выполнять
вычисления без соединения и вызвать `Подключить()` перед работой с интерфейсом.
Автоматического подключения между тестами нет: обращение к интерфейсу до
`Подключить()` завершится ошибкой `not_connected` в этом тесте.

`timeout` задаёт общий срок выполнения набора. Каждый тест получает собственные
переменные и копию `parameters`, а открытые формы и состояние базы сохраняются
между тестами. Подготовку и очистку интерфейса задают сами сценарии.
По умолчанию корень поиска библиотек — переданный каталог, а для списка — каталоги
перечисленных файлов. При необходимости задайте общий `roots` явно.

Ответ содержит `suite: true`, результаты тестов в `tests`, счётчики
`passed`, `failed`, `skipped`, `checked`, `total` в `summary` и исключённые при
сборе файлы с причинами в `excluded`. Каждый выполненный тест содержит свой результат,
ошибку, сообщения, длительность и шаги. В ответ включается до 1000 UI-шагов на весь
набор; `steps_total` и `steps_truncated` у теста показывают полноту его списка.
В журнале действия группируются по тестам; ограничения ответа не сокращают журнал.
Максимум — 256 тестов и 256 различных загруженных файлов вместе с зависимостями.

## Проверка и результат

`check_only=True` разбирает сценарий и все его статически заданные зависимости
без выполнения UI-действий. Проверяются синтаксис поддерживаемого подмножества,
имена функций/методов, разрешение файлов и типы сценариев из JSON-файлов Тестера.
Проверка не доказывает существование полей в конкретной базе и соответствие
фактических значений параметров вызываемым операциям.
Если имя во вложенном `Вызвать`/`Позвать` вычисляется из переменных, проверка
возвращает его место в `dynamic_calls`. Такой файл разрешается и проверяется
при достижении вызова, перед выполнением вложенного сценария.

В ответе выполнения:

- `result` — значение, возвращённое сценарием;
- `sources` — пути и SHA-256 загруженных исходников;
- `steps` — UI-операции с файлом, строкой, результатом и длительностью;
- `messages` — тексты сообщений `Сообщить` и `ВСтудию`;
- `message_details` — эти сообщения со статусом, файлом и строкой сценария;
- при ошибке — `code`, `error`, `path`, `line`, при вложенном вызове также `call_stack`.

Python API поднимает обычный `ActionError` с этим словарём в `result`.
Получить отказ как словарь можно через
`client.call('run_compatible_scenario', check=False, ...)`.

В ответ помещаются первые 1000 UI-шагов; `steps_total` и `steps_truncated`
показывают общее число и усечение. Включённый журнал содержит операции,
включая предварительную проверку адресата. Его настройки HTML, Allure и
скриншотов применяются и здесь.

`timeout` — общий срок исполнения, по умолчанию 1800 секунд; допустимо
положительное число до 86400. Он ограничивает циклы, паузы и сетевое ожидание.
Принудительный `disconnect` прерывает выполнение. Истечение срока не отменяет
операцию, уже отправленную в 1С. Автоматического повторного запуска сценария нет.

## Поддерживаемое поведение Тестера

В готовом сценарии можно сохранить следующие команды и способы работы.
Для частично совместимых команд отличия перечислены
в [ограничениях](#ограничения-совместимости).

| Возможность сценария Тестера | Что поддерживается |
| --- | --- |
| Отключиться от приложения | `Отключить` / `Disconnect`: закрыть соединение; с `Истина` сначала запросить закрытие главного окна. `Подключить()` после отключения восстанавливает соединение с последним выбранным адресом и портом. |
| Сообщить о ходе сценария | `ВСтудию` / `VStudio`, `Сообщить` / `Message`: текст в результате и журнале; у `Сообщить` поддержан второй аргумент `СтатусСообщения`. |
| Подготовить параметры задания | `ЗонаПараметров` / `ParametersSpace`: метод `JobRecord()` возвращает новую структуру `Scenario`, `PinApplication`, `PinVersion`, `CloseAllAfter=Истина`, `Disconnect=Истина`. Первые три поля изначально `Неопределено`. |
| Открыть форму и выбрать текущий объект | `Коммандос` / `Commando`, `ГлавноеОкно.ВыполнитьКоманду`, `Здесь` / `With`, `НайтиФорму` / `FindForm`. |
| Перейти по меню | `Меню` / `OpenMenu`: путь через `/`, с открытием раздела и выбором команды. |
| Получить окно и его команды | `ПолучитьОкно` / `GetWindow`, `ПолучитьСсылки` / `GetLinks`: объекты для поиска, чтения свойств и нажатия команд. |
| Прочитать главное меню | `ПолучитьГлавноеМеню` / `GetMainMenu`: разделы, группы и команды с навигационными ссылками. |
| Прочитать форму и сравнить изменения | `ПолучитьЭлементыАктивногоОкна` / `GetActiveWindowControls`, `ПолучитьИзмененияОкна` / `GetActiveWindowChanges`: дерево элементов и текст изменений относительно предыдущего чтения. |
| Дождаться формы или элемента | `Дождаться` / `Waiting`: поиск по имени или заголовку с ограниченным временем ожидания. |
| Найти элемент и прочитать значение | `Получить` / `Get` возвращает объект; `Взять` / `Fetch` — его значение. Поиск по заголовку, шаблонам `*`/`?`, имени с `!`/`#`, пути `Группа / Поле`. |
| Заполнить форму и выполнить действия | `Установить` / `Set`, `Нажать` / `Click`, `Фокус` / `Activate`, `Очистить` / `Clear`, `Выбрать` / `Choose`, `Подобрать` / `Pick`. |
| Ввести значение с автоподбором | `Ввести` / `Put`, `ВнестиЗначение` / `EnterValue`: ввод текста, ожидание списка, выбор первого предложения и необязательная проверка выбранного значения. |
| Проверить заполнение и состояние элементов | `Проверить` / `Check`, `ПроверитьСтатус` / `CheckState`: значение, видимость, доступность и режим только для чтения. |
| Сравнить результаты | `Заявить` / `Assert`: равенство и неравенство, сравнение чисел, истина/ложь, неопределённое значение, `Null`, заполненность, пустота, существование, диапазон, содержимое, длина и отрицание. |
| Найти строку и проверить таблицу | `КСтроке` / `GotoRow`, `ПроверитьТаблицу` / `CheckTable` с текстовым эталоном, параметрами и проверкой порядка, количества строк и состава колонок. |
| Получить содержимое таблицы | `ПолучитьСодержимоеТаблицы` / `GetTableContent`: массив строк со значениями и заголовками колонок, до 100 строк. |
| Перемещаться по строкам | `ПерейтиКПервойСтроке` / `GotoFirstRow`, `ПерейтиКПоследнейСтроке` / `GotoLastRow`, `ПерейтиКСледующейСтроке` / `GotoNextRow`, `ПерейтиКПредыдущейСтроке` / `GotoPreviousRow` принимают имя таблицы или полученный объект. |
| Перейти к следующему элементу и проверить вкладку | `Далее` / `Next` у текущей формы или таблицы; `ТекущаяВкладка` / `CurrentTab` возвращает объект страницы группы. |
| Открыть карточку значения | `ОткрытьЗначениеВПолеВвода` / `OpenValueInInputField` для поля ввода, в том числе колонки таблицы. |
| Работать с деревом | `РаскрытьСтрокуДерева` / `ExpandTreeRow`, `СвернутьСтрокуДерева` / `CollapseTreeRow`, `ПерейтиНаУровеньНиже` / `GoOneLevelDown`, `ПерейтиНаУровеньВыше` / `GoOneLevelUp`. |
| Обратиться к ячейке отчёта или строке таблицы | Селекторы `[R2C1]`, именованной области и номера строки `[3]` в командах `Взять`, `Получить`, `Фокус`, `Установить`. |
| Нажать ссылку в форматированной надписи | `Нажать("!Справка [2]")` или выбор ссылки по её тексту. |
| Проверить сообщения об ошибках | `ПроверитьОшибки` / `CheckErrors`, `ПолучитьСообщения` / `GetMessages`, `НайтиСообщения` / `FindMessages` с шаблоном. |
| Записать свою ошибку или остановиться | `ЗаписатьОшибку` / `LogError` сохраняет диагностику и продолжает выполнение; `Стоп` / `Stop` вызывает перехватываемое исключение. |
| Закрыть формы | `Закрыть` / `Close`, `ЗакрытьВсе` / `ЗакрытьВсё` / `CloseAll`; закрытие рабочих окон с отменой ввода и отказом от сохранения. Служебная обработка остаётся открытой. |
| Сохранить отчёт в Excel | `ПолучитьСодержимоеТабличногоДокумента` / `GetSpreadsheetContent`: файл XLSX и путь к нему. |
| Сделать снимок по команде | `ПолучитьСнимок` / `GetScreenshot`: путь к PNG; `Снимок` / `Screenshot`: двоичные данные изображения. |
| Вызвать библиотечный или вложенный сценарий | `Вызвать` / `Call`, `Позвать` / `Run`; статическое или вычисляемое имя, передача параметров и возврат результата. |
| Передать параметры и общий контекст | `_` — параметр вызова; `__` — общий контекст теста и его вложенных вызовов; `тут` / `this` — структура текущего сценария; `ИмяПриложения` / `AppName` берётся из `application_name`. |
| Повторить действия или обработать ожидаемую ошибку | Условия, циклы, локальные функции и процедуры, `Попытка/Исключение`, `ОписаниеОшибки()` и повторный `ВызватьИсключение;`. |
| Сделать паузу или вывести сообщение | `Пауза` / `Pause`, `Сообщить` / `Message`. |
| Прочитать переменную окружения | `ПеременнаяСреды` / `SystemVariable`: значение переменной процесса Testpilot, пустая строка при её отсутствии. |
| Сохранить сведения о подготовленных тестовых данных | `СозданоОкружение` / `EnvironmentExists`, `СохранитьОкружение` / `RegisterEnvironment`, `ДанныеОкружения` / `EnvironmentData`; записи общие для вызовов одной сессии Testpilot и разделены по `application_name`. |
| Получить новый идентификатор тестовых данных | `ИДОкружения` / `TestingID`; постоянный счётчик с общей последовательностью для процессов, использующих один каталог состояния. |
| Подготовить представление значения и выбрать текст языка | `Формат` / `Format` для чисел, дат и булевых значений; `НСтр` / `NStr` с явным языком или автоматическим выбором. |
| Выполнить сценарий с командами показа прогресса | `ПрогрессПоказать` / `ProgressShow` и `ПрогрессСкрыть` / `ProgressHide` принимаются без аргументов. Отдельное окно Тестера не открывается. |
| Использовать подключение | `Подключить` / `Connect` принимает аргументы очистки ошибок, порта и компьютера и выбирает клиент для дальнейших действий сценария. Готовое подключение используется повторно, к новому адресу создаётся подключение. По умолчанию проверяет ошибки и при их наличии закрывает рабочие окна; первый аргумент `Ложь` отключает проверку и очистку. |
| Выполнить набор тестов из выгрузки Тестера | Запуск каталога с отбором сценариев по JSON или старому формату `.1c.bsl`; запуск явного списка файлов в указанном порядке. |

Поддерживаются русские и английские ключевые слова, строки, числа, даты, булевы значения,
`Неопределено`, массивы, структуры и соответствия. Объект, полученный командой
`Получить`, можно передать вложенному сценарию и использовать дальше. Допустимые
обращения к нему и функции обработки значений перечислены в
[справке по BSL-вызовам](BSL.md).

Параметр `Тип` при поиске элемента, как в Тестере, задаётся строкой:
`Поле`, `Таблица`, `Кнопка`, `Группа`, `Декорация` или соответствующим английским
названием `Field`, `Table`, `Button`, `Group`, `Decoration`.

Если поиск по заголовку нашёл несколько элементов, выбирается первый, как в
Тестере. В `messages` результата сценария добавляется предупреждение с именами
и типами совпавших элементов. Уточнить поиск можно через `!ИмяЭлемента` или
путь `Группа / Поле`.

При обычном завершении выполняется проверка сообщений об ошибках и восстанавливается
прежний текущий объект. `СтандартнаяОбработка = Ложь` / `StandardProcessing = False`
отключает это поведение. Общий таймаут и аварийный обрыв соединения останавливают сценарий,
даже если в нём есть `Попытка/Исключение`.

`Здесь("Заголовок")` сначала ищет окно по заголовку, затем его форму;
если окна нет — ищет форму по её заголовку. `ПолучитьОкно("Заголовок")`
ожидает появления окна до трёх секунд, в пределах общего таймаута сценария.

`Фокус` и команды заполнения/нажатия подготавливают элемент перед действием:
выбирают первую строку при обращении к колонке без выделенных строк,
пропускают повторную активацию текущего поля. Если перед подготовкой поля
выпадающий список был закрыт, после установки фокуса выполняется попытка его
закрытия. Отказ 1С при этом дополнительном закрытии игнорируется, как в Тестере;
ошибка самой активации прерывает действие. Ранее открытый список сохраняется.

`Выбрать` / `Choose` возвращает объект поля после принятой команды начала
выбора. Обработчик конфигурации может выполнить выбор без отдельного окна;
его отсутствие само по себе не прерывает совместимый сценарий.

`Взять` / `Fetch` для флажка возвращает булево значение. Если представление
не удалось преобразовать или 1С отказала в его чтении, выполняется чтение
отображаемого текста. При отказе и этого чтения возвращается пустая строка,
как в Тестере. Таймаут и потеря связи остаются ошибками.

При отказе 1С в чтении обычного поля через `Взять` также возвращается пустая
строка и сценарий продолжается. Ошибки чтения ячейки таблицы или области
табличного документа прерывают выполнение, как и в Тестере. Прямые методы
объекта, например `GetDisplayedText`, сохраняют исходный отказ чтения.

## Переменные окружения и параметры запуска

`ПеременнаяСреды("TEST_FILES")` / `SystemVariable("TEST_FILES")` возвращает
строку из окружения процесса Testpilot: MCP-сервера или Python-теста,
который запускает сценарий. Если переменной нет, возвращается пустая строка.

`ПараметрыЗапуска` и `LaunchParameters` изначально ссылаются на одно пустое
соответствие. Можно записать значения для использования во вложенных сценариях:

```bsl
ПараметрыЗапуска.Вставить("КаталогФайлов", ПеременнаяСреды("TEST_FILES"));
```

Во вложенном сценарии значение доступно через
`LaunchParameters["КаталогФайлов"]` или `ПараметрыЗапуска["КаталогФайлов"]`.
Ключи чувствительны к регистру; отсутствующий ключ возвращает `Неопределено`.
Каждый отдельный тест получает новое соответствие.
Аргумент `parameters`, переданный при вызове инструмента, доступен в `_`;
он не заполняет `ПараметрыЗапуска` автоматически.

## Описание формы и её изменения

`ПолучитьЭлементыАктивногоОкна()` возвращает структуру активной управляемой формы
с вложенными `Items`: имена `ID`, заголовки `TitleText`, типы элементов,
значения полей, подсказки и текущий элемент. Как в Тестере, скрытые и недоступные
элементы пропускаются вместе с их потомками. Если управляемой формы нет,
возвращается `Неопределено`.

У поля и колонки с подтверждённым запретом редактирования добавляется
`ReadOnly: Истина`. Если запрета нет или свойство не удалось прочитать, поле
`ReadOnly` отсутствует. У непустого табличного документа в `Value.Hint` добавляется
подсказка Тестера о получении XLSX через `GetSpreadsheetContent`.

При подключённой актуальной `Testpilot.epf` описание автоматически дополняется:

- `AllowsTextInput: Ложь`, если у поля запрещено редактирование текста и не задан
  `ReadOnly: Истина`. Это не запрещает заполнение поля через выбор.
- `InputHint` — непустой подсказкой внутри поля.
- `Type` — представлением вида или типа настоящего элемента формы, например
  `Поле ввода` / `Input field`; у формы — `Форма клиентского приложения`.

Эти свойства читаются у конкретного экземпляра формы по уникальному идентификатору.
Исходники конфигурации и разрешение произвольного кода не требуются.
Недоступное свойство пропускается. При отсутствии обработки или этой возможности
в её старой версии используется описание через тестовый протокол.

Без обогащения через обработку строки `Type` соответствуют варианту встроенного языка базы Тестера:
по умолчанию русскому (`ТестируемоеПолеФормы`); для английского задайте
`TesterScriptVariant="en"` (`TestedFormField`). Значения `FieldType`, `GroupType`,
`DecorationType` и текст `Hint` зависят отдельно от языка интерфейса:
`TesterLanguage`, затем языка из подключённой обработки, затем языка ОС.
Например, для английских названий без обработки:

```bsl
TesterScriptVariant = "en";
TesterLanguage = "en";
Описание = ПолучитьЭлементыАктивногоОкна();
```

Типы, прочитанные через обработку, возвращаются на языке платформы клиента;
`TesterScriptVariant` и `TesterLanguage` их не переводят.

Отказ платформы прочитать необязательное свойство — видимость, доступность,
запрет редактирования, подсказку или состояние кнопки — не прерывает описание.
Непрочитанное свойство пропускается; если неизвестна видимость или доступность,
элемент остаётся в описании. Обрыв связи и исчезновение элемента остаются ошибками.
Отказ чтения значения обычного поля обрабатывается как в Тестере: у поля ввода
возвращается пустой `Value`, у остальных полей пустое значение не включается.
Для флажка сначала дополнительно пробуется чтение отображаемого текста.
Поэтому пустой `Value` в таком описании сам по себе не доказывает, что поле пусто.

```bsl
Здесь();
Описание = ПолучитьЭлементыАктивногоОкна();
Установить("!Наименование", "Новое наименование");
Изменения = ПолучитьИзмененияОкна();
Сообщить(Изменения);
```

При повторном чтении той же выбранной формы `ПолучитьИзмененияОкна()` возвращает
текст: `~` — изменение, `+` — добавление, `-` — удаление, `*` — изменение порядка.
Например: `~ Items[Наименование].Value: "" -> "Новое наименование"`.
Если изменений нет, результат — строка `"No changes."`.
Первый вызов, переход на другую форму или отсутствие текущего объекта,
выбранного через `Здесь`, возвращают полное описание формы вместо текста разницы.
Если управляемой формы нет, эта команда возвращает ошибку.

Обе команды после успешного чтения запоминают новое описание. Оно общее для теста
и его вложенных сценариев; следующий отдельный тест начинает сравнение заново.
Открытие формы через `Коммандос` с активацией, переход по `Меню` и закрытие формы
сбрасывают описание. Повторное `Здесь()` для той же формы его сохраняет.
Ошибка чтения не заменяет последнее успешное описание.
Подсказки кешируются по форме и имени элемента в пределах теста, включая вложенные вызовы.

Чтение сохраняет фокус и незавершённый ввод. У таблиц возвращаются колонки,
текущая колонка и состояние редактирования, без обхода строк. Для содержимого
таблицы используется отдельная команда `ПолучитьСодержимоеТаблицы`.
Дополнения из расширения и исходников конфигурации описаны в ограничениях ниже.

## Даты

Можно создавать даты, вычислять период и передавать результат в команды Тестера:

```bsl
Здесь();
ДатаДокумента = Дата(2026, 9, 25);
Установить("!Дата", ДатаДокумента);
Далее();
Проверить("!Дата", ДатаДокумента);
Заявить(ДобавитьМесяц(ДатаДокумента, 1)).Равно(Дата(2026, 10, 25));
```

Поддерживаются литералы вроде `'20260925'`, сравнения дат, арифметика в секундах,
компоненты даты, начало/конец дня и месяца, добавление месяцев.
`ТекущаяДата()` берёт местное время компьютера с исполнителем сценария.
Полный список и сигнатуры — в [справке BSL](BSL.md#вычисления-и-значения-в-сценариях).

Для `Установить`, `Проверить`, `Строка` и `Сообщить` формат даты задаётся переменной
исполнителя **`TesterDateFormat`**. По умолчанию числовой формат определяется по
региональному представлению даты из Testpilot.epf. Без обработки или со старой
обработкой, не передающей эти сведения, используются региональные настройки ОС
компьютера, где работает Testpilot. Формат сохраняется на время сценария отдельно
для каждого подключённого клиента. Его можно задать явно:

```bsl
TesterDateFormat = "M/d/yyyy h:mm:ss tt";
// Другие примеры:
// TesterDateFormat = "dd/MM/yyyy HH:mm";
// TesterDateFormat = "yyyy-MM-dd";
// TesterDateFormat = "yyyy-MM-dd'T'HH:mm:ss";
// TesterDateFormat = "dd.MM.yy";
// TesterDateFormat = "HH:mm:ss";
// TesterDateFormat = "d MMMM yyyy";
```

Это настройка Testpilot, общая для теста и вложенных вызовов. Явное значение имеет
приоритет; `Неопределено` или пустая строка возвращают автоматический выбор.
Поддержаны даты с годом `yyyy` или `yy`: день–месяц–год, месяц–день–год,
год–месяц–день; разделители `.`, `/`, `-`, пробелы и литералы в одинарных кавычках.
Время — 24-часовое `H`/`HH` или 12-часовое `h`/`hh` с `tt` (`AM`/`PM`),
минуты `m`/`mm`, необязательные секунды `s`/`ss`.
При вводе день и месяц дополняются нулём, чтобы значение принимали также поля
без времени. При чтении учитываются пробелы маски; отсутствие секунд означает
ноль секунд, а отсутствие времени — полночь. Неоднозначные даты разбираются
по выбранному формату: `01/02/2026` не переключает автоматически день и месяц.
При `yy` двузначный год разбирается как 2000–2049 для `00–49` и 1950–1999
для `50–99`; четырёхзначный год сохраняется целиком. Это правило проверено на
вводе в поле даты 1С. Формат только времени, например `HH:mm:ss`, даёт дату
`01.01.0001` с указанным временем.
`MMM` и `MMMM` поддерживают сокращённые и полные русские и английские названия
месяцев. При чтении допустимы оба языка; при формировании строки используется
региональный язык клиента, а без этих сведений — ОС сервера Testpilot.
Для названий месяцев формат нужно задать явно. Он должен соответствовать
тексту, который возвращает поле: собственный формат отображения формы может
отличаться от регионального. Если автоматический формат определить не удалось,
задайте `TesterDateFormat` явно.
Эта настройка описывает ввод и чтение дат. Для самостоятельного получения строки
поддержан `Формат` / `Format`, описанный в [справке BSL](BSL.md#форматирование-и-языковые-строки).

Дату можно передать в параметрах при запуске BSL-сценария.
Например, аргументы MCP-инструмента `tc_run_compatible_scenario`:

```json
{
  "path": "scenario.bsl",
  "parameters": {
    "date": {"$type": "date", "value": "2026-09-25T12:34:56"}
  }
}
```

Если тот же сценарий запускается из Python-теста, в `parameters` можно передать
обычный объект Python `datetime` без часового пояса и микросекунд:

```python
from datetime import datetime

client.run_compatible_scenario(
    path="scenario.bsl",
    parameters={"date": datetime(2026, 9, 25, 12, 34, 56)},
)
```

В обоих случаях внутри файла `scenario.bsl` параметр `date` доступен через
`_.date` как значение типа `Дата`:

```bsl
ДатаДокумента = _.date;
Заявить(Год(ДатаДокумента)).Равно(2026);
```

Сам сценарий также может создать дату: `ДатаДокумента = Дата(2026, 9, 25);`.
Передавать параметр для этого не требуется.

Дата в результате сценария возвращается в виде
`{"$type": "date", "value": "2026-09-25T12:34:56"}`.
Даты можно передавать вложенным сценариям и хранить в массивах и структурах. `Взять` по-прежнему
возвращает текст поля; `Проверить` разбирает его как дату, когда ожидаемое значение
имеет тип `Дата`. В `ПроверитьТаблицу` дата также сравнивается по значению,
если ячейка эталона целиком содержит ссылку на параметр даты, например `%ДатаПоставки`.

## Строки и коллекции

Вспомогательные вычисления сценария выполняются в Python-исполнителе.
Доступны `СтрРазделить` / `StrSplit`, `СтрСоединить` / `StrConcat`,
`Найти` / `Find`, `СтрНайти` / `StrFind`, `Символ` / `Char`.
Константы перевода строки, возврата каретки и табуляции:
`Символы.ПС` / `Chars.LF`, `Символы.ВК` / `Chars.CR`, `Символы.Таб` / `Chars.Tab`.

```bsl
Строки = СтрРазделить("Товар А;Товар Б", ";");
Строки.Вставить(1, "Товар В");
Позиция = Строки.Найти("Товар Б"); // 2, индексы массива начинаются с нуля.
Строки.Установить(Позиция, "Товар Г");
Строки.Удалить(0);
Сообщить(СтрСоединить(Строки, Символы.ПС));
```

У структуры добавлены `Удалить` / `Delete` и `Очистить` / `Clear`.
Условия поиска строк, необязательные аргументы и ограничения —
в [справке BSL](BSL.md#строковые-функции).

## Остановка и диагностические записи

```bsl
Попытка
    Стоп("Не выполнено условие проверки");
Исключение
    ЗаписатьОшибку(ОписаниеОшибки());
КонецПопытки;
// Сценарий продолжает работу.
```

`Стоп(Причина)` вызывает исключение с переданным текстом. Без перехвата
запуск возвращает `ok=false`, `code=scenario_stopped`. Причину можно опустить.

`ЗаписатьОшибку(Текст)` добавляет запись в `diagnostics`: сообщение `message`,
путь сценария `path`, номер строки `line` и путь к PNG `screenshot`.
При включённом журнале ошибка и снимок также попадают в HTML/Allure, даже если
автоматические снимки выключены. Общий запрет снимков продолжает действовать.
Если снимок недоступен, сообщение сохраняется с `screenshot_error`.
Таймаут сценария и разрыв соединения останавливают выполнение.

Эта команда сама не вызывает исключения и не меняет успешное завершение запуска:
`ok=true` означает, что сценарий выполнился, а его собственные замечания находятся
в `diagnostics`. В журнале соответствующий шаг отмечен ошибкой. Если замечание
должно провалить тест, вызовите `Стоп` или используйте `Заявить`.
Диагностика вложенных сценариев включается в текущий запуск; у набора каждый
тест имеет собственный список. Предел — 1000 записей на тест.

## Закрытие форм, выгрузка отчётов и снимки

`ЗакрытьВсе()` закрывает рабочие окна, начиная с активного. При необходимости
отменяет незавершённый ввод поля или строки и отвечает «Нет» на распознанный
вопрос о сохранении изменений. В диалоге `MessageBox` с кнопкой «Отменить ввод»
или `Cancel entry` нажимает эту кнопку и продолжает закрытие. Это работает
и для уже открытого диалога, и если он возник во время отмены редактирования.
Уже записанные данные остаются в базе.
Главное окно, начальная страница и служебная обработка Testpilot остаются открытыми.
Если закрытию мешает неизвестный диалог, выполнение останавливается с его текстом.
Успешное завершение означает, что доступных для закрытия рабочих окон больше нет.

```bsl
Здесь("Отчёт*");
ФайлОтчёта = ПолучитьСодержимоеТабличногоДокумента("!ОтчетТабличныйДокумент");
ФайлСнимка = ПолучитьСнимок();
ЗакрытьВсе();
Возврат Новый Структура("Отчёт,Снимок", ФайлОтчёта, ФайлСнимка);
```

`ПолучитьСодержимоеТабличногоДокумента(Имя, Источник)` принимает селектор поля
табличного документа либо полученный объект; источник необязателен. Возвращает
путь к XLSX. Сохранение выполняется напрямую в XLSX; после принятия команды
до 15 секунд ожидается доступный завершённый файл, в пределах общего таймаута.
Сбой очистки ответа файлового диалога не скрывает сохранённый файл: диагностика
попадает в `messages`. Клиент 1С и Testpilot должны иметь доступ к одному пути;
обычный вариант — работа на одном компьютере.

`ПолучитьСнимок()` возвращает путь к PNG. `Снимок(Шаблон, Сжатие)` возвращает
двоичные данные, которые можно передать вложенному сценарию, записать методом
`Записать(Путь)` / `Write(Path)` или узнать их `Размер()` / `Size()` в байтах:

```bsl
Изображение = Снимок();
Изображение.Записать(_.ПутьСнимка);
Возврат Изображение.Размер();
```

Снимки делаются механизмом Testpilot для подключённого клиента на Windows или
Linux, включая isolated. Пустой или пропущенный шаблон выбирает текущее окно;
непустой должен совпадать с его заголовком (`*` и `?` поддерживаются).
`Сжатие=Истина` включает дополнительное сжатие PNG без изменения пикселей.
Неполный снимок возвращает `screenshot_incomplete`. Явный снимок включается
в активный журнал даже при отключённых автоматических снимках.

Файлы остаются во временном каталоге ОС компьютера Testpilot после завершения
сценария; их пути можно использовать в Python-тесте. Метод `Записать` сохраняет
по переданному пути. Суммарно за тест допускается до 64 МиБ данных снимков.
При возврате самих двоичных данных наружу используется объект
`{"$type":"binary","base64":"..."}`.

## Меню, окна и команды

```bsl
Меню("Продажи / Заказы клиентов");
Здесь();
Окно = ПолучитьОкно();
Заявить(Окно.Заголовок).Заполнено();

Команды = ПолучитьСсылки(Окно);
Кнопка = Команды.НайтиОбъект(
    Тип("ТестируемаяКнопкаКомандногоИнтерфейса"), "Связанные документы");
Если Кнопка <> Неопределено Тогда
    Кнопка.Нажать();
КонецЕсли;

Разделы = ПолучитьГлавноеМеню();
```

Заголовки в примере зависят от конфигурации и языка интерфейса.
`Меню(Путь)` ищет группы и кнопки главного командного интерфейса. Промежуточный
раздел открывается нажатием; оставшаяся часть пути ищется в его меню функций,
чтобы одноимённая открытая вкладка не подменяла команду. Допустимы короткие пути
`Раздел / Команда` и пути с промежуточными группами.

`ПолучитьОкно(Форма)` принимает объект формы, окна или заголовок окна с `*`/`?`.
Без аргумента используется текущий объект, выбранный через `Здесь`, а если его
нет — активное окно. Для объекта формы сначала ищется окно с этой же формой.
Если она уже закрыта, возвращается первое окно с таким же `FormName`; если
совпадений нет — `Неопределено`. Это позволяет получить окно заново открытой
формы. Сохранённые поля и кнопки закрытой формы остаются недействительными.
`ПолучитьСсылки(Форма)` использует тот же поиск и возвращает командный интерфейс этого
окна. `ГлавноеОкно.GetCommandInterface()` обращается к главному окну независимо
от активной формы. Командный интерфейс и его группы поддерживают поиск и обход
дочерних объектов; найденные кнопки — `Нажать()` и свойство `URL`.
Их можно использовать как источник поиска, например
`Нажать("Имя команды", ПолучитьСсылки(Окно))`.

У окна доступны `Заголовок` / `Caption`, `IsMain`, `НачальнаяСтраница` / `HomePage`, `URL`, получение формы
через `GetObject()` без аргументов и закрытие через `Close()`.
Сохранённый объект проверяется перед дальнейшими обращениями: закрытое окно
или заменённая команда дают ошибку доступности.

`Приложение` / `App` обращается к клиенту, на котором запущен сценарий:

- `ПолучитьАктивноеОкно()` / `GetActiveWindow()` — активное рабочее окно.
- `ПолучитьПодчиненныеОбъекты()` / `GetChildObjects()` — окна приложения.
- `НайтиОбъект()` / `FindObject()`, `НайтиОбъекты()` / `FindObjects()`,
  `ПолучитьОбъект()` / `GetObject()` — поиск по всему приложению с теми же
  параметрами типа, заголовка, имени и ожидания, что у объектов формы.

Например, строка из сценариев Тестера выбирает форму активного окна:

```bsl
Здесь(Приложение.ПолучитьАктивноеОкно().ПолучитьОбъект());
```

Объект доступен с начала сценария: подключение уже создано в Testpilot.
Служебная обработка исключается из поиска и списка окон. Возвращённые окна,
формы и элементы поддерживают описанные здесь свойства и методы.

`ПолучитьГлавноеМеню()` возвращает массив структур:

- раздел: `Subsystem`, `Items`;
- группа внутри раздела: `Group`, `Items`;
- команда: `Item`, `URL`.

Описание получается обходом разделов интерфейса. Команда открывает их меню,
после успешного обхода закрывает последнее меню повторным нажатием раздела.
Если раздел открывает форму без меню команд, вызывается `ЗакрытьВсе()`,
раздел пропускается и обход продолжается. При этом закрываются все рабочие
окна, включая открытые до вызова; служебная обработка Testpilot сохраняется.
Если меню команд нет ни у одного раздела, возвращается пустой массив.
Пропущенный последний раздел повторно не нажимается, чтобы не открыть его форму заново.
Текущий раздел может измениться. Список отражает команды, доступные текущему
пользователю. Ошибка чтения или закрытия окон прерывает обход; неполный результат не выдаётся
как полное описание меню.

## Ввод с автоподбором, сообщения и содержимое таблицы

```bsl
Ввести("!Контрагент", "Тестовый");
ВнестиЗначение("!Контрагент", "Тестовый покупатель");

Сообщения = НайтиСообщения("Не заполнено*Контрагент");
Заявить(Сообщения.Количество()).Равно(0);

Строки = ПолучитьСодержимоеТаблицы("!Товары");
Для Каждого Строка Из Строки Цикл
    Заявить(Строка.Номенклатура.Value).Заполнено();
КонецЦикла;
```

`Ввести(Имя, Значение, Источник, Тип, ПроверятьЗначение)` принимает те же
источник и тип элемента, что `Установить`. Последние три аргумента необязательны,
проверка значения по умолчанию выключена. `ВнестиЗначение(Имя, Значение)`
включает её. Если платформа сообщила о сформированном списке и список открыт,
выбирается первое предложение. Проверка сравнивает выбранный текст с переданным
без учёта регистра; при несовпадении поле очищается и сценарий получает ошибку.
Без списка дополнительное сравнение не выполняется. Отказ 1С при ожидании
автоподбора считается отсутствием списка. После отказа текстового ввода
проверяется доступность редактирования; если поле допускает редактирование,
выполняется попытка выбора из списка по переданному тексту. Это относится и
к `Установить`. Таймаут, потеря связи и ошибка самого запасного выбора
прерывают выполнение.
Обе команды возвращают объект поля. Начатое командой редактирование строки
завершается после успешного ввода; уже начатое ранее остаётся открытым.

`НайтиСообщения(Шаблон)` возвращает массив полных текстов подходящих сообщений.
Поиск без учёта регистра, внутри текста: `*` означает один или больше символов,
`?` — один символ. Поддерживаются группы, альтернативы и границы регулярных
выражений, например `"^(Ошибка|Error):"`. Сообщения читаются из окна;
при их отсутствии проверяются элементы `Message` и `ErrorInfo`.
Чтение сообщений и `ПроверитьОшибки` не открывают закрытую панель, в том числе
при стандартной проверке в конце сценария; текущее окно ошибки проверяется и при закрытой панели.

`ПолучитьСодержимоеТаблицы(Имя, Источник)` принимает имя или объект таблицы;
источник необязателен. Возвращается массив структур. Ключ каждой колонки —
**имя элемента формы**, а её значение — структура с полями `Title` (заголовок)
и `Value` (значение ячейки). Как в Тестере, из текста удаляются все фрагменты
`<…>`, например `<b>Товар</b>` превращается в `Товар`. Это правило действует
и при чтении ячеек таблицы через `Взять`. Пробелы сохраняются.
Пример одной строки:

```bsl
// Строки[0].Номенклатура.Title = "Номенклатура"
// Строки[0].Номенклатура.Value = "Тестовый товар"
```

Числовой текст преобразуется автоматически. Разделители выбираются по приоритету:

1. Явное значение `LatestSeparatorsInfo` в сценарии.
2. Региональные настройки сеанса 1С, переданные актуальной Testpilot.epf при открытии.
3. Региональные настройки ОС, где работает MCP-сервер или Python-тест.

На Windows используются настройки пользователя, от которого запущен Testpilot,
включая заданные вручную разделители. На Linux и macOS — настройки локали процесса
(`LC_ALL`, `LC_NUMERIC`, `LANG`). Чтение не меняет локаль процесса Testpilot.
Автоматические значения кэшируются в пределах теста отдельно для каждого клиента;
переключение подключения выбирает его значения. Старая обработка без сведений о
разделителях также использует запасной источник — ОС. Ошибка связи при обнаружении
обработки не подменяется успешным чтением настроек ОС.

Чтобы явно задать разделители, используемые в форме:

```bsl
LatestSeparatorsInfo = Новый Структура("Fractions,Groups", ",", " ");
Строки = ПолучитьСодержимоеТаблицы("!Товары");
// "1 234,50" становится числом 1234.5; "00123" — числом 123.
```

`Fractions` — десятичный разделитель, `Groups` — разделитель групп разрядов.
Для формата `1,234.50` задайте соответственно `"."` и `","`.
Автоматически выбранные значения доступны в `LatestSeparatorsInfo` после чтения
таблицы или описания окна. Присваивание `Неопределено` возвращает автоматический
выбор. Некорректные числа сохраняются текстом. Если настройки ОС не удаётся
прочитать, возвращается `regional_settings_unavailable`; разделители можно задать явно.
При включённом преобразовании числовой текст с ведущими нулями также становится
числом, как в Тестере: `"000123"` → `123`, `"01,50"` → `1.5`.
Это относится и к цифровым кодам — тип реквизита по тексту ячейки неизвестен.
Настройка действует на текущий запуск и его вложенные сценарии.

Строку поиска динамического списка можно заполнить через `Установить`:

```bsl
Здесь();
TesterDynamicListSearchWaitTime = 5;
Установить("!ДополнениеСтрокаПоиска", "Тестовая компания");
Строки = ПолучитьСодержимоеТаблицы("!Список");
Установить("!ДополнениеСтрокаПоиска", ""); // Сбросить поиск.
```

Используйте имя поискового элемента своей формы. После ввода выдерживается
`TesterDynamicListSearchWaitTime` секунд (по умолчанию 2, как в Тестере).
Это настраиваемая пауза, а не сигнал готовности списка; для медленного поиска
увеличьте её. Сценарий должен также дождаться первоначальной загрузки списка
перед вводом поиска. Ожидание учитывает общий таймаут сценария. `Взять` для такого
элемента возвращает текст поиска; для ячейки таблицы — текст без указанной
служебной подсветки.

Пример с параметрами — [list_search.bsl](../../../examples/compatible_scenarios/tester/list_search.bsl).

Команда завершает редактирование строки, переходит к первой и выделяет строки.
При множественном выделении порядок результата определяется платформой.
При одиночном выделении выполняется последовательный обход до конца таблицы.
Полученный отказ перехода на следующую строку завершает обход: возвращаются
прочитанные строки, затем текущей снова становится первая строка, как в Тестере.
Таймаут, обрыв связи и исчезновение таблицы остаются ошибками.
Как в Тестере, предел — 100 строк; превышение возвращает ошибку, а не усечённый
результат. Чтение меняет текущую строку и выделение.
На проверенных 8.3.27 и 8.5.1 таблица с одиночным выделением не сообщала о конце:
такой обход завершается с `table_end_unavailable`. Для неё полный результат
пока получить нельзя. Таблицы с множественным выделением читаются одним набором.
Если после выделения получена лишь одна строка, отличить единственную строку
от ограничения одиночного выделения не удаётся: применяется тот же обход.

## Ожидание, переходы и заполнение строк

Для обращения к строке через `[номер]` можно указать заголовок колонки с её номером:

```bsl
СпециальныеПоля.LineNo = "Номер строки";
Значение = Взять("!Товары / !Номенклатура [20]");
```

Здесь ищется значение `20` в колонке «Номер строки». Если такой видимой колонки
нет, выполняется переход к двадцатой строке от начала таблицы.
`SpecialFields.LineNo` — английский вариант того же свойства. Настройка общая
для теста и его вложенных сценариев. По умолчанию используется `#` для английского
языка и `N` для остальных, как в Тестере. Значение определяется при первом обращении
к настройке или переходе по номеру строки: сначала учитывается `TesterLanguage`,
затем язык пользователя из Testpilot.epf, а без него — региональные настройки ОС
сервера Testpilot. Чтобы задать язык явно, присвойте `TesterLanguage = "en"` до
первого такого обращения. Явное присваивание `LineNo` заменяет заголовок по умолчанию.
Если колонка найдена, но нужного номера в ней нет, возвращается `row_not_found`.

```bsl
Заявить(Дождаться("Заказ клиента*", 10)).ЭтоИстина();
Здесь("Заказ клиента*");
Заявить(Дождаться("!Товары", 3, Тип("ТестируемаяТаблицаФормы"))).ЭтоИстина();

ПерейтиКПервойСтроке("!Товары");
ПерейтиКСледующейСтроке("!Товары");
Подобрать("!Номенклатура", "Тестовый товар");
ОткрытьЗначениеВПолеВвода("!Номенклатура");
```

`Дождаться(Имя, Таймаут, Тип)` возвращает `Истина`, если объект найден,
или `Ложь`, если время ожидания истекло. По умолчанию ищется форма, таймаут —
3 секунды. Префиксы `!`/`#` обозначают имя, без них ищется заголовок;
поддерживаются `*`/`?`. Тип задаётся через `Тип(...)`: форма, поле, таблица,
кнопка, группа или декорация. Поиск идёт по окнам приложения и не меняет
текущий объект сценария. Нулевой таймаут выполняет один поиск. Ошибка связи
и общий таймаут сценария остаются ошибками, а не результатом `Ложь`.

Четыре команды перехода по строкам завершают редактирование текущей строки,
затем перемещаются без расширения выделения. Необязательный второй аргумент
задаёт форму или другой поддерживаемый источник поиска таблицы.
`Далее()` переходит к следующему элементу объекта, выбранного через `Здесь`;
текущий объект должен быть формой или таблицей.
`ТекущаяВкладка(Имя, Источник, Тип)` возвращает объект текущей страницы
либо `Неопределено`, если страница отсутствует. Например:
`Заявить(ТекущаяВкладка("!Страницы").Имя).Равно("Основное")`.

`Очистить("Поле1,Поле2")` очищает поля по очереди и возвращает последний объект.
Для колонки таблицы `Очистить`, `Подобрать` и `ОткрытьЗначениеВПолеВвода`
начинают редактирование при необходимости и после успеха завершают только
начатое ими редактирование. Если строка уже редактировалась, этот режим сохраняется.
`Подобрать` использует уже открытый список либо открывает его перед выбором.
`Выбрать` также подготавливает редактирование колонки, но оставляет его открытым
для дальнейшего выбора. При ошибке операции принудительного завершения или
отмены ввода не происходит.

## Проверки состояния, дерева и гиперссылок

```bsl
ПроверитьСтатус("!Номенклатура", "Видимость");
ПроверитьСтатус("!Количество", "Доступность");
ПроверитьСтатус("!Итого", "ТолькоЧтение", Истина);
Заявить(Взять("!Наименование")).Заполнено().Содержит("Тест");
Заявить(10).Между(1, 100);
Заявить("ABC").ИмеетДлину(3);

РаскрытьСтрокуДерева("!Список");
СвернутьСтрокуДерева("!Список");
ПерейтиНаУровеньНиже("!Список");
ПерейтиНаУровеньВыше("!Список");

Получить("!Дополнительно").Развернуть();
Нажать("!Справка [2]");        // Вторая ссылка в форматированной надписи.
Нажать("!Справка [Подробнее]"); // Ссылка с указанным текстом.
```

`ПроверитьСтатус` / `CheckState` принимает имя или список имён через запятую,
состояние `Видимость` / `Visible`, `Доступность` / `Enable`,
`ТолькоЧтение` / `ReadOnly`, ожидаемый флаг (по умолчанию `Истина`),
необязательные источник и тип элемента. Неизвестное состояние вызывает ошибку.

В `Заявить` доступны также `ЭтоNull`, `ЕстьNull` / `IsNull`,
`Пусто` / `Empty`, `Существует` / `Exists`,
`Заполнено` / `Filled`, `Между` / `Between`, `Содержит` / `Contains`,
`ИмеетДлину` / `Вмещает` / `Has`, `That(значение, сообщение)`.
Границы `Между` включены. `Содержит` ищет подстроку в строке или значение
в массиве, структуре, соответствии. `Ложь` считается заполненным значением,
ноль и пустая коллекция — незаполненными. `That` задаёт новое значение проверки.

`Null` — отдельное значение, отличное от `Неопределено`. Оно равно самому себе,
имеет тип `Тип("Null")`, считается незаполненным и несуществующим в проверках
`Заявить`. `Строка(Null)` возвращает пустую строку; числовые операции,
сравнение на больше/меньше и использование `Null` как условия вызывают ошибку.

```bsl
Заявить(Null).ЭтоNull();
Заявить(Неопределено).Не_().ЭтоNull();
Заявить(Null = Неопределено).ЭтоЛожь();
```

При передаче параметров или результата сценария `Null` представляется как
`{"$type":"null"}`, а `Неопределено` — как JSON `null` (в Python — `None`).
Например, `parameters={"value": {"$type": "null"}}` даёт в сценарии
`_.value` типа `Null`. Это работает и внутри массивов и структур.

`Подключить()` / `Connect()` по умолчанию читает текущую ошибку клиента, как
при обычном запуске сценария в Тестере. То же поведение у `Подключить(Истина)`
и `Подключить(Неопределено)`. Если ошибки
нет, проверяет сообщения и текст окна ошибки. При обнаруженной ошибке или
сообщении вызывает ту же очистку окон, что `ЗакрытьВсе`: несохранённые изменения
отменяются, служебная обработка, главное окно и начальная страница сохраняются.
При отсутствии ошибок рабочие окна остаются открытыми. Ошибки связи и отказ
закрытия возвращаются сценарию.

`Подключить(Ложь)` / `Connect(False)` использует подключение без проверки ошибок
и очистки окон. Пропуск первого аргумента при указании порта или компьютера,
например `Подключить(, 1600)`, сохраняет проверку и очистку по умолчанию.

Чтобы продолжить сценарий на другом запущенном клиенте тестирования, укажите
порт и при необходимости компьютер:

```bsl
Подключить(Ложь, 1599, "localhost");
Здесь(Приложение.ПолучитьАктивноеОкно().ПолучитьОбъект());

Подключить(Ложь, 1600, "test-host");
Здесь(Приложение.ПолучитьАктивноеОкно().ПолучитьОбъект());
```

Пропущенные порт и компьютер берутся из `AppData.Port` и `AppData.Computer`.
Изначально это адрес подключения, с которого запущен сценарий. Порт — целое
число от 1 до 65535. При создании подключения используется версия протокола
текущего клиента; для другой версии платформы заранее подключите её через
MCP с нужным `version`, затем выберите адрес в сценарии.

После переключения `Приложение`, `ГлавноеОкно` и последующие команды относятся
к выбранному клиенту; текущую форму нужно выбрать заново. Сохранённый объект
прежнего клиента отклоняется, пока сценарий не переключится обратно.
Если подключение не удалось, прежнее остаётся выбранным.

Выбор действует до конца текущего сценария, включая вложенные вызовы.
Внешний Python `Client` и следующий тест набора используют исходное подключение.
Если сценарий явно отключил его, следующий тест начинает работу без соединения;
`Подключить()` без адреса и порта восстанавливает исходное подключение набора.
Дополнительные соединения, созданные сценарием, отключаются при его завершении;
сами приложения 1С продолжают работать. Ранее существовавшие подключения
сохраняются. Ошибки освобождения соединений возвращаются в `diagnostics`.

`Отключить()` разрывает выбранное соединение. В том же сценарии или следующем
тесте набора можно продолжить вычисления и затем вызвать `Подключить()`.
`Отключить(Истина)` сначала запрашивает закрытие главного окна, затем отключается.
Как и в Тестере, эта команда не ждёт завершения процесса: вопрос конфигурации
о выходе может оставить приложение открытым.

Прямые методы `Приложение.Подключить()` / `App.Connect()` и
`Приложение.Отключить()` / `App.Disconnect()` также поддержаны, без аргументов.
Отключение сохраняет сам объект приложения; его можно подключить снова:

```bsl
Приложение.Отключить();
Приложение.Подключить();
```

Прямое подключение использует адрес этого объекта, даже если `AppData.Computer`
или `AppData.Port` изменены. Эти методы не выполняют очистку рабочих окон,
предусмотренную глобальной командой `Подключить()`.

Команды дерева завершают редактирование текущей строки перед переходом.
`Нажать` на группу пробует раскрыть её, при отказе платформы — свернуть.
Если нажатие кнопки формы получило отказ платформы, `Нажать` / `Click`
проверяет доступность и видимость кнопки и её родителей, у формы — доступность.
Если всё доступно и видно, сценарий продолжается без повторного нажатия,
как в Тестере. Сам отказ остаётся в журнале; продолжение не подтверждает,
что кнопка выполнила действие. Таймауты, обрывы связи и ошибки проверки
не подавляются. Прямой вызов `Кнопка.Нажать()` сохраняет ошибку платформы.
У надписи без указания ссылки сначала выбирается первая ссылка; если платформа
отказывает, выполняется обычное нажатие. При явно указанной ссылке её отсутствие
возвращает ошибку. Номера в `[скобках]` начинаются с 1; у прямого метода
`ClickFormattedStringHyperlink` — с 0.

## Сравнение таблицы формы

Проверка учитывает все строки. Если при выделении получается только одна строка,
исполнитель обходит таблицу последовательно. Успех требует подтверждённого конца
таблицы: отказа перехода или отсутствия выбранной строки после перехода. Если
платформа продолжает сообщать последнюю строку без отказа, возвращается
`table_end_unavailable`; совпадение текста соседних строк не считается концом.

`ПроверитьТаблицу` / `CheckTable` принимает текст эталона, необязательную структуру
параметров, структуру настроек и форму-источник:

```bsl
Эталон = "!Товары
|N | !ТоварыНоменклатура | Количество
|1 | Тестовый товар А   | %КоличествоА
|2 | Тестовый товар Б   | 2";

ПроверитьТаблицу(Эталон, Новый Структура("КоличествоА", 10));
// Для проверки полного состава и порядка колонок:
// ПроверитьТаблицу(Эталон, ПараметрыЭталона, Новый Структура("Strictly", Истина));
```

Готовый [сценарий с параметрами](../../../examples/compatible_scenarios/tester/table_check.bsl)
можно запускать через MCP или Python API после открытия нужной формы.

Первая строка — селектор таблицы, вторая — заголовки колонок. Первый столбец
эталона служит для номеров строк и не сравнивается с данными формы.
Разделители — `|` или запятая; текст с разделителем можно заключить в одинарные
кавычки. Колонка задаётся заголовком либо именем с `!`/`#`.

Сравниваются значения, порядок и точное количество строк. По умолчанию можно
перечислить только нужные колонки и расположить их в удобном порядке.
`Strictly = Истина` требует полного состава и порядка колонок формы.
Эталон без строк данных проверяет пустую таблицу.

`%имя` подставляет параметр. Если вся ячейка — числовой параметр, значение
сравнивается как число, включая представления с пробелами и десятичной запятой.
Если параметр имеет тип `Дата`, прочитанный текст разбирается по `TesterDateFormat`
и сравнивается с датой. Поле без времени соответствует полуночи. Например:

```bsl
Эталон = "!Товары
|N | !ДатаПоставки
|1 | %ДатаПоставки";
ПроверитьТаблицу(Эталон, Новый Структура("ДатаПоставки", Дата(2026, 9, 25)));
```

В строковых значениях `*` означает один или несколько символов, `?` — один;
шаблон ищется внутри текста ячейки без учёта регистра. `\*`, `\?`, `\%`
обозначают сами символы. Если есть неэкранированный `*` или `?`, шаблон
преобразуется в регулярное выражение по правилам Тестера: скобки, альтернативы
`|`, классы `[…]`, повторения `+`/`{…}` и границы `^`/`$` сохраняют свой смысл;
точка и обратная косая черта считаются обычными символами.
Например, `'(A|B)*'` в ячейке эталона соответствует `AX` или `bX`. Кавычки
нужны, чтобы `|` внутри шаблона не разделял колонки эталона.
Без неэкранированных `*` и `?` выполняется точное сравнение с учётом регистра.
Ошибка регулярного выражения возвращается как ошибка шаблона.

Проверка завершает редактирование строки этой таблицы, очищает выделение и
перемещает текущую строку. Читаются доступные для выделения строки с учётом
фильтров и свёрнутых групп, затем ячейки сравниваются в порядке интерфейса.
При несовпадении возвращаются строка, колонка и сравниваемые значения;
при отказе чтения — ошибка операции. Одновременное изменение списка другим
пользователем не обеспечивает неизменного снимка данных.

## Ограничения совместимости сценариев

Раздел описывает перенос готового сценария Тестера: какие его команды пока
не выполняются, где поведение отличается и какие зависимости придётся заменить.
Сверка ведётся по командам и поведению Тестера. Наличие похожего инструмента
Testpilot само по себе не обеспечивает выполнение соответствующей команды сценария.

Отличия сведений, передаваемых ИИ-агенту, вынесены в отдельный раздел в конце
документа. Здесь перечислены ограничения исполнения и случаи, когда требуется
изменить код сценария.

Здесь есть как небольшие недобавленные сопоставления, так и зависимости от
собственной базы и интерфейса Тестера. Например, `ПроверитьШаблон` требует
загрузки MXL и переноса правил
сравнения областей.

Для переноса выгрузите сценарий вместе с вызываемыми библиотеками, задайте
`roots` и параметры, затем выполните `check_only=True`. Эта проверка находит
неподдерживаемый код и отсутствующие статические зависимости; проверять действия
и результаты всё равно нужно запуском на своей базе. Нельзя заранее обещать,
что любой готовый сценарий потребует только небольших правок: объём зависит
от команд и библиотек, которые он использует.

### Команды работы с интерфейсом, которых пока нет

| Команда Тестера: русское / английское имя | Что пока недоступно в совместимом сценарии |
| --- | --- |
| `ПроверитьШаблон` / `CheckTemplate` | **Не реализована команда сравнения отчёта с MXL-эталоном.** В Тестере она загружает эталон и сравнивает заданные области табличного документа. Testpilot не загружает такой эталон и не выполняет эти проверки. Пока отдельные ячейки можно проверить явно через `Взять` / `Проверить`. |
| `МаксимизироватьОкно` / `MaximizeWindow`, `МинимизироватьОкно` / `MinimizeWindow` | **Не реализованы обе команды.** Тестер находит окно ОС по заголовку и разворачивает или сворачивает его. В совместимом сценарии Testpilot эти вызовы отклоняются. |

В таблице отдельно указаны поведение Тестера и отличие Testpilot.
«Не реализовано» означает отсутствующую возможность; «отличается» — другой
результат или порядок действий при тех же условиях. Одинаковое поведение
команд описано в примерах выше и здесь не считается ограничением.

| Команда и ситуация | Как работает в Тестере | Что не реализовано или отличается в Testpilot |
| --- | --- | --- |
| `Подключить` / `Connect`: не переданы адрес или порт | Берёт `AppData.Computer` и `AppData.Port`, заполненные настройками приложения из своей базы. | **Отличается источник начальных значений.** Эти поля заполняются адресом исходного подключения Testpilot. Для прежнего сохранённого описания укажите `metadata_path`. Формат структуры совпадает с `Meta.epf` Тестера. |

Формат для каждого поля автоматически не определяется; если он отличается от регионального, задайте его явно. Названия месяцев на других языках не поддержаны. |
| `ЗакрытьВсе`, `ЗакрытьВсё` / `CloseAll`: служебная обработка Testpilot | Закрывает рабочие окна, не выделяя эту обработку отдельно. | **Намеренное отличие:** окно служебной обработки остаётся открытым. Сценарий не должен ожидать его закрытия этой командой. |

Неизвестный вопрос, неоднозначная кнопка или неустранённый отказ дают ошибку; оставшиеся окна могут не закрыться. Нестандартный диалог нужно обработать в сценарии. |

Переданный шаблон лишь проверяется на совпадение с активным окном 1С; при несовпадении возвращается ошибка. `ScreenshotsLocator` не используется. |

Размер и байты снимка не обязаны совпадать с результатом компоненты Тестера. |
| `ПолучитьСодержимоеТабличногоДокумента` / `GetSpreadsheetContent` | Сохраняет MXL, затем преобразует его в XLSX средствами 1С. | **Отличается способ экспорта.** Клиент сразу сохраняет XLSX; путь к нему возвращается после проверки файла. Промежуточное преобразование MXL не выполняется, поэтому полное совпадение оформления экспортов не проверено. Testpilot должен иметь доступ к сохранённому файлу; передача файла с удалённого клиента не реализована. |
| `ПолучитьСообщения`, `ПроверитьОшибки`, `НайтиСообщения`: старые окна ошибок | На платформах до 8.3.15 дополнительно читает поля `Field1` / `Поле1`. | **Не реализована эта ветка для старых платформ.** Если текст ошибки доступен только в таких полях, команды его не прочитают. На 8.3.27 и 8.5.1 это не отличие штатного пути чтения сообщений. |
| `НайтиСообщения`, `ПроверитьТаблицу`: сложный шаблон поиска | Использует регулярные выражения внешней компоненты Тестера. | **Другой механизм поиска и дополнительные пределы.** Используется Python `regex`; совместимость всех специальных конструкций не проверена. Обработка одного сообщения или сравнение одной ячейки дольше 0,25 с дают ошибку; общий таймаут сценария также действует. Для `НайтиСообщения` дополнительно действует предел длины шаблона 4096 символов. |
| `ПолучитьСодержимоеТаблицы` и описание окна: числовые разделители | Получает разделители из контекста клиента либо региональных настроек сеанса Тестера. | **Отличается запасной источник.** Без сведений от Testpilot.epf используются региональные настройки ОС, где работает Testpilot. При отличиях от тестируемого клиента задайте `LatestSeparatorsInfo` явно. |
| `ПолучитьСодержимоеТаблицы`: у нескольких колонок одинаковый заголовок | Получает значение строки по заголовку для каждой колонки; одинаковые заголовки могут дать одно значение в нескольких колонках. | **Вместо такого результата возвращается ошибка неоднозначности.** Отдельные значения этих колонок нужно читать адресно, по именам элементов. Если значение колонки вообще не пришло от платформы, её `Value` будет `Неопределено`, а не подтверждённым пустым текстом. |
| `ПолучитьСодержимоеТаблицы`: при одиночном выделении переход с последней строки не сообщает об окончании | Продолжает обход; действует предел количества читаемых строк. Полученный отказ перехода завершает чтение. | **Отличается диагностика предела.** Если окончание не подтверждено за 100 строк, возвращается `table_end_unavailable`. Таймаут, обрыв связи и исчезновение таблицы не считаются успешным окончанием чтения. |
| Автоматическая проверка ошибки приложения: сбой самого чтения | Подавляет исключение от `ПолучитьТекущуюИнформациюОбОшибке` и продолжает сценарий. | **Ошибки связи не подавляются.** Таймаут или обрыв возвращаются как ошибка выполнения; полученный отказ платформы допускает продолжение. |
| `ПроверитьТаблицу` / `CheckTable`: при одиночном выделении переход с последней строки не сообщает об окончании | Сравнивает строки последовательным обходом, ориентируясь на отказ перехода. | **Нельзя подтвердить точное количество строк без признака окончания.** После сравнения эталона возвращается `table_end_unavailable`, если следующий переход успешен и выбранная строка остаётся. Это может означать лишнюю строку или отсутствие перехода с последней строки. |
| `ПроверитьТаблицу`: серверный вариант команды | Серверная библиотека Тестера может сравнить переданную таблицу значений с эталоном. | **Не реализован серверный вариант.** Поддержана проверка таблицы открытой формы по текстовому эталону. Передать вместо неё объект `ТаблицаЗначений` нельзя; MXL-эталоны также не загружаются. |
| Обращение к строке таблицы по номеру: язык колонки `N` или `#` | Определяет язык по интерфейсу самого Тестера. | **Отличается источник языка.** Используется `TesterLanguage`, иначе язык пользователя из Testpilot.epf или региональные настройки ОС сервера Testpilot. Если язык Тестера был другим, задайте `TesterLanguage` или `СпециальныеПоля.LineNo` явно. Правило выбора колонки совпадает: `#` для английского, `N` для остальных. |
| Обычные команды поиска, чтения и изменения служебной формы Testpilot | Не выделяет эту внешнюю обработку среди остальных форм приложения. | **Намеренное ограничение:** служебная форма скрыта из обычного поиска и защищена от чтения, изменения и закрытия. Сценарий не может обращаться к её полям и кнопкам как к обычной форме. |

`Установить` и прямой `ВвестиТекст` выполняют ввод с `finish=False`.
Завершение ввода отдельного поля не добавляется автоматически; для таблицы и
области табличного документа действуют описанные выше операции завершения редактирования.
Для типов без специального обработчика `Установить` пробует обычный ввод текста,
в том числе для поля текстового документа. Успешность ввода определяет платформа;
её отказ возвращается сценарию.

### Сценарий сам анализирует описание окна

Эта таблица применима только к коду, который вызывает
`ПолучитьЭлементыАктивногоОкна` или `ПолучитьИзмененияОкна`.
Если сценарий и его библиотеки их не используют, эти ограничения его не затрагивают.

| Что делает код сценария | Отличие от Тестера и необходимые изменения |
| --- | --- |
| Проверяет дополнительные свойства из описания окна | `ReadOnly` доступен через протокол, `AllowsTextInput` и `InputHint` — через актуальную подключённую `Testpilot.epf`. Другие дополнения, например `DataType`, `Mandatory`, `WarningOnEdit` и `WarningOnEditText`, пока не добавляются. Проверки этих полей описания нужно адаптировать. |
| Извлекает строки таблицы из описания окна | Строки в описание не включаются. Их нужно читать отдельно через `ПолучитьСодержимоеТаблицы` или `Взять`. |
| Сравнивает названия типов или всё описание с эталоном | С актуальной обработкой `Type` читается у настоящего элемента формы; без неё используются названия объектов тестового протокола. Настройка языка описана выше. Полный состав описания расширения Тестера не воспроизводится, поэтому сравнение всего описания с таким эталоном требует адаптации. |
| Рассчитывает получить неполное описание при любой ошибке чтения | Отказы чтения необязательных свойств пропускаются, как описано выше. Ошибка обязательных сведений, связи, исчезновение элемента или изменение формы/фокуса прерывают чтение. Действуют пределы: 10 000 элементов, глубина 100 и 1 000 000 символов описания. |

### Собственные вычисления и вспомогательные библиотеки

Сценарий может содержать условия, циклы, локальные функции и
`Попытка/Исключение`; параметры, строки, числа, даты и коллекции обрабатываются
внутри исполнителя. Но произвольный BSL из сценария или библиотеки Тестера
ещё не поддерживается полностью. При переносе потребуется изменить код, если он:

- использует ссылки базы, таблицы или деревья значений, MXL,
  файловые, сетевые либо COM-объекты; для двоичных данных снимка поддержаны
  только запись в файл и получение размера;
- вызывает отсутствующие функции обработки значений либо неподдерживаемые
  методы коллекций. `Формат` / `Format` и `НСтр` / `NStr` поддержаны;
  локали форматирования ограничены `ru_RU`, `en_US` и `en_GB`;
- содержит директивы клиент/сервер, условный препроцессор, обработчики событий,
  асинхронные процедуры, выполняет строку как код или запускает команду ОС;
- рассчитывает на доступ локальной функции к произвольным переменным тела
  сценария или обход причины/стека ошибки как объектов. Поддержаны описание
  ошибки и её текстовые подробности; организационные `#Область` / `#КонецОбласти`
  и английские варианты также принимаются.

Для проверки конкретного выражения есть
[справка по поддерживаемым BSL-вызовам и значениям](BSL.md).
Она также описывает обращения через точку к результату `Получить`, например
`Таблица.УдалитьСтроку()`. Такие обращения проверяются в исходном сценарии
и его библиотеках; переписывать внутренние вызовы самого Тестера не требуется.

Массивы, структуры и соответствия поддержаны также в фиксированном варианте.
У `СпискаЗначений` доступны создание, чтение и изменение элементов, поиск,
копирование, загрузка/выгрузка значений, заполнение пометок, сортировка,
перемещение и идентификаторы элементов. Картинки и диалоги списка пока не поддержаны.
Сортировка строк требует системной ICU; порядок проверен на Windows 8.3.27 и 8.5.1
для кириллицы, латиницы, регистра, диакритики и знаков. Полное совпадение всех
символов и версий ICU не заявляется.

Файлы библиотек, вызываемые через `Вызвать`/`Позвать`, нужно предоставить вместе
со сценарием и указать их каталоги в `roots`. Они проходят ту же проверку, что
и основной файл. Наличие поддержанной команды в основном сценарии не устраняет
зависимости внутри вызываемой библиотеки. Совместимость всего `CommonTests`
или любой другой библиотеки целиком не заявляется.

Пример: `Общее.Выбрать` может вызвать переданный ему сценарий создания объекта.
Тогда для переноса нужны сам библиотечный метод, сценарий создания и их зависимости.
Код, который читает настройки или окружение из базы Тестера, требует отдельной
замены — эти зависимости перечислены ниже.

### Контекст, приложения и служебные функции Тестера

`СвойстваПриложения` / `AppData` — общий для теста и его вложенных вызовов
контекст подключения. Поддержаны пять полей:

| Поле | Значение |
| --- | --- |
| `Computer`, `Port` | Адрес и порт для `Подключить()` без соответствующего аргумента. Изначально берутся из исходного подключения Testpilot; можно изменить в сценарии. |
| `Connected` | Признак подключения. Обновляется при подключении/отключении и учитывает обнаруженное закрытие соединения. Сам по себе не гарантирует ответ 1С на следующий запрос. |
| `ConnectedHost`, `ConnectedPort` | Адрес последней попытки подключения, в том числе неудачной. Изначально — исходное подключение. |

```bsl
Если Не AppData.Connected Тогда
    Подключить();
КонецЕсли;
Порт = СвойстваПриложения.Port;
```

Обе переменные ссылаются на один объект. После `Подключить(Ложь, 1600)` поле
`ConnectedPort` станет 1600, а `Port` сохранит прежнее значение. Для изменения
порта по умолчанию присвойте `AppData.Port = 1600`.

**Остальные штатные поля AppData не заполняются:** например, ссылка `Application`
на объект базы Тестера и настройки запуска из его карточки приложения.
При неудачном переключении ранее работавшее подключение сохраняется; поэтому
`Connected` может оставаться истинным, а `ConnectedHost`/`ConnectedPort` указывать
на неудачную попытку. Это отличается от повторного подключения с отключением
внутри Тестера. Сам контекст AppData не предназначен для сохранения как запись
окружения; сохраните нужные значения в обычной структуре.

Не предоставляются глобальные объекты `ЗаголовокДиалогов` / `DialogsTitle`, `Debug`, `Chronograph`,
`ScreenshotsLocator`,
`ВыполняетсяДелегированноеЗадание` / `RunningDelegatedJob`, `ЯАгент` / `IAmAgent`.
У `Приложение` / `App` поддержаны получение активного окна, список окон, поиск
объектов и `ПолучитьТекущуюИнформациюОбОшибке` / `GetCurrentErrorInfo`.
Поддержаны также прямые методы `Приложение.Подключить()` и
`Приложение.Отключить()`; они описаны в разделе работы с подключениями выше.

Между операторами сценария автоматически читается текущая ошибка тестируемого
клиента. Новая ошибка прерывает выполнение с `application_error`; её можно поймать
через `Попытка/Исключение`. Подробности доступны через
`ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`. Одна и та же ошибка повторно
не выбрасывается, пока клиент не сообщит об её отсутствии или о другой ошибке.
Проверка относится к выбранному подключению и действует во вложенных сценариях.

`ИгнорироватьОшибки = Истина` или `IgnoreErrors = True` отключает эти автоматические
проверки. По умолчанию оба значения — `Ложь`; проверка включена, когда оба ложны.
Это не отменяет отказ команды, явную `ПроверитьОшибки()` или проверку сообщений
в конце при `СтандартнаяОбработка = Истина`.
`ПараметрыЗапуска` / `LaunchParameters` поддержаны как общее соответствие,
но настройки и строка запуска самого Тестера в него не загружаются. Параметры
конкретного вызова передаются через `parameters` и доступны в `_`.
`__` общий только для одного теста и его вложенных вызовов; между отдельными
тестами набора он не сохраняется.

### Сведения о тестовых окружениях

`СохранитьОкружение(ID, Данные)` / `RegisterEnvironment` сохраняет сведения о
подготовленных тестовых данных. `СозданоОкружение(ID)` / `EnvironmentExists`
проверяет наличие записи; `ДанныеОкружения(ID)` / `EnvironmentData` возвращает её
данные либо `Неопределено`, если записи нет.

```bsl
Если Не СозданоОкружение("Buyer") Тогда
    // Здесь сценарий создаёт покупателя через интерфейс.
    СохранитьОкружение("Buyer", Новый Структура("Имя", "Тестовый покупатель"));
КонецЕсли;
Покупатель = ДанныеОкружения("Buyer");
```

Записи доступны следующим тестам набора и следующим вызовам
`run_compatible_scenario` того же `Client` Python API или работающего MCP-сервера.
`application_name` разделяет записи разных приложений. Вложенный вызов библиотеки
другого приложения продолжает использовать окружение исходного запуска.
Отключение и переподключение 1С записи не удаляет.

Сохранение под тем же ID заменяет данные. Как в регистре Тестера, ID — строка
до 10 символов: более длинное значение сокращается, регистр букв не различается.
Без аргумента `Данные` сохраняется `Неопределено`, но запись считается созданной.
Поддержаны строки, числа, даты, булевы значения, `Неопределено`, `Null`, массивы,
структуры и соответствия, их фиксированные варианты, списки значений и их элементы.
Сохраняется копия; изменение исходной
структуры или результата чтения не меняет запись. Объекты интерфейса не сохраняются.

Для сохранения между перезапусками передайте `environments_path`:

```python
client.run_compatible_scenario(
    path="tests/ЗаказКлиента.bsl",
    application_name="УТ",
    environments_path="test-results/environments.sqlite3",
)
```

В MCP используется тот же параметр. Относительный путь отсчитывается от рабочего
каталога процесса Testpilot. Файл и недостающие каталоги создаются при первом
`СохранитьОкружение`; простое чтение отсутствующего файла и `check_only` их не создают.
Все тесты набора и вложенные сценарии используют выбранный файл. Последующий
запуск с тем же путём может прочитать сохранённые сведения. Разные процессы могут
одновременно работать с одним файлом; записи изменяются короткими транзакциями.

В файле записи разделяются по **базе, `application_name` и ID окружения**.
База определяется из `launch_client`: полный путь файловой базы либо сервер
и имя серверной базы. Порт тестового клиента и пользователь 1С не входят в ключ.
При переключении подключения используется база выбранного клиента; вызов библиотеки
другого приложения сохраняет `application_name` исходного сценария.
Разные сетевые имена одного сервера или разные пути к одной базе не объединяются
по их физическому расположению. Для независимых наборов одной базы можно использовать
разные файлы или `application_name`.

Для клиента, подключённого только по адресу и порту, база неизвестна: постоянные
операции возвращают `environment_base_unknown`. Запустите клиент через Testpilot.
Без `environments_path` по-прежнему действует хранение в памяти текущей сессии;
независимые `Client` и перезапуск MCP начинают отдельное хранилище.

SQLite сохраняет типы дат, точные числа, массивы, структуры, соответствия,
их фиксированные варианты, списки значений с представлениями и пометками и
`Неопределено`/`Null`; размер одной сериализованной записи ограничен 1 МиБ,
вложенность — 100, число коллекций — 10 000. Ошибка чтения или повреждение файла
не сбрасывают записи. При конкурирующей записи одного ключа остаётся последняя
успешно сохранённая версия. Проверка `СозданоОкружение` и последующее создание
прикладных данных не составляют общую транзакцию: такая последовательность сама
по себе не исключает двойное создание объектов параллельными тестами.

**Отличие от Тестера:** используется память или выбранный SQLite-файл, а не регистр
его базы. Разделение в SQLite идёт по тестируемой базе и имени приложения вместо
сессии пользователя Тестера. Записи из базы Тестера не импортируются. Сохраняются
только явно переданные поддержанные значения; прикладные объекты не копируются,
не создаются и не удаляются этой командой.

`ИДОкружения()` / `TestingID()` возвращает следующий идентификатор по алгоритму
Тестера: `A001`, `A002`, …, `A009`, `A00A`, …, `A00Z`, `A010`.
Его можно использовать в имени тестового объекта или в `СохранитьОкружение`:

```bsl
Идентификатор = ИДОкружения();
ИмяПокупателя = "Покупатель " + Идентификатор;
СохранитьОкружение(Идентификатор, Новый Структура("Имя", ИмяПокупателя));
```

Счётчик сохраняется между запусками; параллельные процессы с одним хранилищем
получают разные значения. По умолчанию файл `testing-id.sqlite3` расположен
в `%LOCALAPPDATA%/1c-testpilot` на Windows, в `$XDG_STATE_HOME/1c-testpilot`
на Linux/macOS (при отсутствии переменной — `~/.local/state/1c-testpilot`).
`TC1C_TESTER_STATE_DIR` задаёт другой каталог; относительный путь отсчитывается
от рабочего каталога процесса. MCP и Python-тесты одного пользователя с одинаковым
каталогом используют общий счётчик независимо от `application_name`.

**Отличие от Тестера:** его константа ID не читается — это отдельная последовательность
Testpilot. Разные каталоги или компьютеры имеют независимые счётчики. При переносе
сохраните файл счётчика; удаление файла начнёт последовательность заново.
Ошибка чтения или повреждение хранилища не сбрасывают счётчик. После `ZZZZ`
возвращается `testing_id_exhausted`, повторная выдача старых ID не выполняется.

`ПрогрессПоказать()` / `ProgressShow()` и `ПрогрессСкрыть()` / `ProgressHide()`
принимаются и позволяют продолжить готовый сценарий. **Отличие от Тестера:**
отдельный интерфейс показа прогресса не предоставляется. Вызовы не управляют
включением журналов Testpilot.

Следующие служебные команды пока отсутствуют:

| Команды Тестера | Что не переносится автоматически |
| --- | --- |
| `УстановитьПриложение` / `PinApplication`, `УстановитьВерсию` / `SetVersion`, `МояВерсия` / `MyVersion` | Настройки приложения и выбор версий тестируемого приложения/сценариев из базы Тестера. |
| `СоздатьЗадание` / `NewJob`, `ЗапуститьТест` / `RunTest` | Создание заданий агентам Тестера и запуск через его подсистему выполнения. Запуск папок и списков средствами Testpilot описан выше. |
| `ПоместитьСценарии` / `StoreScenarios` | Помещение изменений в хранилище сценариев Тестера. |
| `ОтладкаСтарт` / `DebugStart`, `ПерейтиВКонсоль` / `GotoConsole` | Отладчик и консоль Тестера. |
| `ХронографСтарт` / `RecorderStart`, `ХронографСтоп` / `RecorderStop`, `ХронографОчистить` / `RecorderClean` | Запись, остановка и очистка хронографа Тестера. Журналы Testpilot управляются отдельно. |

Нет доступа к справочникам, регистрам, параметрам сеанса и общим модулям базы
Тестера: `RuntimeSrv`, `Test`, `Environment`, `Conversion`, `DF` и другим.
Обращение `Справочники...` или `Новый Запрос(...)` не перенаправляется в тестируемую
базу. Подключение Testpilot.epf не меняет этого: сценарий совместимости не
отправляется туда для исполнения.

Готовые файлы библиотек тоже должны быть совместимы. Единственное специальное
исключение — известная версия `CommonTests/Общее/ИД.bsl`: она выполняет секундную
паузу и формирует шестнадцатеричный идентификатор на основе времени для обычного
запуска вне редактора. Версия определяется по содержимому файла. Другие варианты
этого файла проверяются и выполняются как обычный сценарий.

### Файлы, наборы и пределы выполнения

- Поддерживаются файлы UTF-8 `.bsl`, `.1c.bsl`, `.1cm.bsl` и описанные выше
  файлы `.dir.*`. Прямой запуск по ссылке или коду объекта из базы Тестера,
  загрузка его хранилища, версий, блокировок редактирования и MXL-вложений не реализованы.
- Соседние JSON-файлы не загружают окружение Тестера. Используются тип сценария
  и отметка удаления при сборе папки; настройки приложения, обработчиков событий,
  версий и параметров из них не применяются.
- Файл с типом `Folder` или `Library` не выполняется как самостоятельный сценарий,
  даже если в нём есть код. При запуске каталога собираются вложенные сценарии;
  код контейнеров не запускается до или после них автоматически.
- Нет запуска через агентов Тестера, расписаний, делегирования заданий, выбора
  приложения из задания, его обработчиков до/после выполнения и восстановления
  окружения. Тесты нашего набора выполняются последовательно и начинают работу
  с исходного подключения, сохраняя его подключённое или явно отключённое состояние;
  внутри теста можно подключаться и переключаться через `Подключить`.
  Настройки запуска веб-клиента и прокси Тестера также не импортируются.
- Порядок папки определяется логическим путём без учёта регистра. Он может
  отличаться от сортировки базы Тестера для отдельных символов. Для точного порядка
  передайте список файлов. Между тестами нет автоматической очистки форм или данных.
- До начала проверяются синтаксис, известные вызовы и статические зависимости,
  включая неисполняемые ветки. Проверка не подтверждает доступность элементов,
  всех свойств и типов во время выполнения. Вычисляемая зависимость проверяется
  при вызове и может дать отказ после уже выполненных действий.
- Пределы: до 256 тестов в наборе, 256 загруженных исходных файлов с зависимостями,
  1 МиБ на файл, 8 388 608 символов суммарного загруженного текста; до 10 000 BSL-файлов при
  обходе каталога. На один тест — до 200 000 шагов вычислений, 10 000 UI-операций,
  1000 сообщений `Сообщить` и глубина вызовов 64. Конструктор массива и
  `Добавить` ограничены 10 000 элементов.
  Конкатенация строк ограничена 1 000 000 символов.
- `timeout` ограничен 86 400 секундами; для набора срок общий. Таймаут и отказ
  не откатывают уже выполненные действия в 1С. В ответ входят до 1000 UI-шагов
  на одиночный сценарий или весь набор, до 1000 исключённых файлов; усечение
  обозначается соответствующими счётчиками и признаками.

## Отличия описания интерфейса для ИИ-агента

Здесь сравниваются сведения, которые агент получает при возврате
`ПолучитьЭлементыАктивногоОкна` / `GetActiveWindowControls` или
`ПолучитьИзмененияОкна` / `GetActiveWindowChanges` через MCP Тестера и через
совместимый исполнитель Testpilot. Это различия результата наблюдения за формой,
а не перечень отсутствующих команд тестирования. Собственные инструменты MCP
Testpilot, например `get_context`, в этой таблице не сравниваются.

| Что получает агент в Тестере | Что отличается в Testpilot |
| --- | --- |
| При доступных расширении и исходниках — дополнительные сведения о типах данных, обязательности заполнения, запрете редактирования и текстового ввода, подсказках внутри полей и предупреждениях | Возвращается `ReadOnly`, а с актуальной обработкой — также `AllowsTextInput` и `InputHint`. Типы данных, обязательность заполнения и предупреждения в описание пока не добавляются. |
| При доступном расширении — строки таблиц и значения текущей строки вместе с описанием формы | В описании есть колонки, текущая колонка и состояние редактирования. Содержимое строк нужно запросить отдельно. |
| Названия типов в строковом представлении 1С, а при подключённом расширении — также описания из него | Актуальная обработка читает представление вида или типа самого элемента. Без неё возвращаются названия объектов тестового протокола. Дополнительные описания из исходников не добавляются. |

Для разработчиков: [устройство исполнителей и добавление формата](../INTERNALS.md).
