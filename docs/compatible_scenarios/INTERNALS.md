# Устройство совместимых сценариев

Совместимые сценарии входят в обычную установку Testpilot. Реализации форматов
находятся в `app/compatible_scenarios/` и загружаются при выборе формата.

```text
MCP / Python API
       │
       ▼
_runtime.tc_run_compatible_scenario
       │
       ▼
compatible_scenarios.run
       │ выбирает формат по framework
       ▼
tester.runner.run
       │
       ├── правила Тестера, файлы, библиотеки, наборы, селекторы
       ├── общие BSL-функции и методы тестового клиента
       └── существующие действия Testpilot → клиент 1С
```

## Папки

```text
app/compatible_scenarios/
├── __init__.py          общий вход run()
├── registry.py          соответствие формата его исполнителю
├── errors.py            ошибка с результатом сценария
├── tester/              реализация совместимости с Тестером
│   ├── runner.py        загрузка BSL, библиотеки, наборы и выполнение
│   ├── ui.py            команды и селекторы Тестера
│   ├── context.py       описание интерфейса
│   ├── connections.py   подключение и переключение приложений
│   ├── environments.py  тестовые окружения
│   ├── regional.py      настройки языка, чисел и дат для сценария
│   └── ...              таблицы, окна, файлы, метаданные, идентификаторы
└── shared/              части, доступные исполнителям разных форматов
    ├── testing.py       объекты и прямые методы тестового клиента
    ├── diff.py          сравнение описаний
    └── bsl/             разбор и выполнение BSL, типы и функции платформы
        ├── language.py
        ├── collections.py
        ├── builtins.py
        ├── strings.py
        ├── dates.py
        ├── formatting.py
        ├── collation.py
        └── binary.py
```

`shared` не импортирует `tester`. Специальные переменные Тестера, автоматическая
проверка ошибок приложения и получение настроек текущего подключения задаются
исполнителем. Интерпретатор получает их через объект `host`; в нём же находятся
счётчики, срок выполнения и вызовы действий. Поэтому другой формат может
использовать общие типы и функции со своим окружением.

`testing.py` сопоставляет методы тестового клиента с существующими действиями
Testpilot. Поиск по строковым селекторам Тестера и его дополнительные правила
остаются в `tester/ui.py`.

## Добавление формата

1. Создать подпапку формата рядом с `tester`, с собственным `__init__.py`.
2. Реализовать `run(runtime, *, path, framework, **options)`: проверку
   `check_only`, выполнение и словарь результата с `ok`. Общий вход передаёт
   параметры и возвращает результат без преобразования.
3. Добавить имя формата и путь к модулю в `registry.FORMATS`, а имя — в
   `Literal` параметра `framework` у `tc_run_compatible_scenario`, чтобы формат
   появился в схеме MCP.
4. Проверить запуск через общий вход, MCP и Python API.

Логику основного обработчика менять не требуется. Общие части
можно подключать по необходимости. Специфичные для формата настройки и команды
реализуются в его папке.
