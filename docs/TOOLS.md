# Инструменты MCP-сервера

Сервер публикует 10 инструментов: каждый отвечает за один тип объектов клиента тестирования, конкретная операция выбирается параметром `action`. Дополнительно доступны пять инструментов обработки Testpilot без `action`: код, запросы, метаданные, список и вызов пользовательских функций. Их доступность определяется настройками и реестром функций подключённой обработки. Ниже параметры для режима `id` по умолчанию. В `off` и `prefix` вместо `ref` используются `key`/`handle`, вместо `root_ref` — `root_key`. Ссылки берутся из обхода дерева (`tc_app(action="get_child_objects")` или `tc_find(action="find_object")`). Звёздочка в колонке «Параметры» помечает обязательный параметр: в объединённой схеме группы все параметры необязательны.

Общий необязательный параметр всех групп — `connection_id`. `ref` определяет подключение автоматически; при нескольких клиентах без `ref` нужно указать `connection_id`. Список клиентов — `tc_session(action="list_connections")`.

Лишние и пропущенные параметры действия возвращаются как `invalid_arguments` с их
именами и правильной сигнатурой; ссылки при таком отказе не проверяются в 1С.

В компактных MCP-ответах `click`, `execute_command`, `choose_from_drop_list` и
`execute_choice_from_choice_list` повторное описание окна заменяется на
`window_changed: false`. Первое или изменившееся описание возвращается в `window`
с `window_changed: true`; изменение заголовка тоже учитывается. Ошибки и диагностика
окна сохраняются. Это не проверка изменений содержимого формы. Полные ответы
(`TC1C_RESPONSE_DETAIL=full`), Python API и журнал сохраняют блок окна.

`select_value` выбирает точный текст через выпадающий список, при необходимости —
через форму выбора. Вместо `value` можно передать `match` с точными значениями
колонок формы выбора:

```python
tc_field(action="select_value", ref="…", value="Ромашка")
tc_field(action="select_value", ref="…", match={"Наименование": "Ромашка", "ИНН": "7701234567"})
```

- `choice_table` — имя таблицы выбора; `choice_column` — заголовок колонки для поиска `value`.
- `data_type` — точное название в стандартном окне выбора типа; `expected` — ожидаемый текст выбранного поля.
- Несколько совпадений или неполное чтение таблицы останавливают выбор. Поиск учитывает текущие отборы и свёрнутые группы; `max_rows` — 1–10000. В условиях позиционирования строки не поддержаны буквальные `*` и `?`.
- Возвращаются принятое значение и способ проверки. Выбор строки и закрытие формы не удостоверяют UUID; `expected` добавляет проверку текста. В строковом списке подпись пункта может отличаться от принятого значения.
- `timeout` — 180 секунд по умолчанию, `0 < timeout ≤ 3600`. При отказе изменения не откатываются; `selection_sent` показывает, отправлялся ли выбор. Для ячейки используется текущая строка, её редактирование автоматически не завершается.

`set_fields` заполняет поля одной формы по порядку. В каждой записи укажите адрес
и один вариант: `text`, `checked` или `select` с параметрами `select_value`:

```python
tc_field(action="set_fields", entries=[
    {"ref": "…", "select": {"value": "Ромашка"}},
    {"ref": "…", "text": "Комментарий"},
    {"ref": "…", "checked": True},
])
```

В `select` можно передать `match` и остальные параметры выбора; `timeout` ограничивает
этот выбор. В конце повторно проверяются все заданные значения. При отказе пакет
останавливается, предыдущие изменения остаются; результат выбора находится в
`results[i].selection`. Порядок заполнения задаёт вызывающий код.

Служебная обработка не требуется. После отказа окно выбора может остаться открытым:
завершите или отмените выбор перед повторным вызовом на исходном поле.

`read_rows`, `find_rows` и `search` принимают `columns=["Код", "Наименование"]`:
возвращаются только указанные колонки в заданном порядке. Названия должны быть точными
и однозначными. По умолчанию возвращаются все колонки и текст без разметки подсветки
поиска 1С; `text_format="raw"` сохраняет исходную разметку. Произвольный HTML не удаляется.
Выбор колонок сокращает ответ, но не объём чтения из 1С; счётчики и признаки усечения сохраняются.

Таблицы с одиночным выделением читаются построчно с возвратом к исходной текущей строке.
Режим определяется через подключённую обработку; без неё результат массового выделения
проверяется, если получено не больше одной строки. Последовательный обход ограничен
10 000 строками, всё чтение — 180 секундами (или оставшимся сроком внешнего действия).
При превышении возвращается ошибка, а не неполный результат с признаком полного чтения.
`max_rows` ограничивает выдачу, включая `0` для одного счётчика. Предыдущее выделение
очищается; `cursor_restored=false` при отказе означает, что вернуть текущую строку не удалось.

`read_rows` и `goto_row` возвращают `inactive_page`, если таблица находится на неактивной
странице. Активируйте страницу из поля `page` и повторите действие; до отказа выделение
и текущая строка не меняются.

`search` вводит текст в строку поиска указанной таблицы и возвращает строки результата:

```python
tc_table(action="search", ref="…", text="Ромашка")
tc_table(action="search", ref="…", text="")  # Очистить поиск.
```

Текущие отборы сохраняются. Проверяются текст поиска и совпадение двух чтений строк
с интервалом `settle_time` (по умолчанию 2 секунды); это наблюдение стабильности,
а не отдельный сигнал завершения поиска от платформы. `max_rows` ограничивает выдачу
(1–10000): при `truncated=true` сравниваются возвращённая часть и общее число строк.
`timeout` ограничивает всё действие: `0 < timeout ≤ 3600`, `0 < settle_time < timeout`.
Нужна стандартная строка поиска внутри таблицы или её командной панели.
Чтение снимает выделение; незавершённое редактирование блокирует действие.
После ошибки поиск может остаться изменённым.

Действия `get_list_settings`, `get_list_settings_fields` и `set_list_settings` адресуются
таблице списка и открывают её стандартную форму «Настройка списка». Служебная обработка
не требуется. Перед вызовом завершите редактирование строки и активируйте окно списка.

```python
tc_table(action="get_list_settings_fields", ref="…", section="filters")
tc_table(action="set_list_settings", ref="…",
         filters=[{"field": "Наименование", "comparison": "contains", "value": "Кабель"}],
         orders=[{"field": "Наименование", "direction": "asc"}], replace=True)
```

- `field` — точное название доступного поля, `value` — вводимый текст. Неоднозначные названия отклоняются.
- Сравнения: `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `contains`, `not_contains`, `filled`, `not_filled`. Последние два — без `value`. Сортировка: `asc` / `desc`; `enabled=False` отключает условие или сортировку.
- По умолчанию настройки добавляются. `replace=True` заменяет только переданные разделы; пустой список очищает соответствующий раздел.
- Чтение возвращает отображаемые значения: отборы — с корнем и группами, сортировки — по приоритету. Свёрнутые ветви доступных полей не обходятся.
- `max_rows`: 1–10000 строк на таблицу, превышение — ошибка. `timeout`: по умолчанию 180 секунд, диапазон `0 < timeout ≤ 3600` на всю операцию.

При успехе запись применяет настройки и закрывает форму. При ошибке или таймауте
сделанные изменения не откатываются; ответ показывает этап и выполненные действия.
Чтение закрывает только самостоятельно открытую форму. Поддерживается стандартная
форма настройки списка; создание вложенных групп условий не поддерживается.

Для компактного обзора передайте `include_commands=False` (без кнопок и командных групп),
`visible_only=True` (без заведомо скрытых элементов и неактивных страниц) или `root_ref`
(поддерево элемента). Неизвестная видимость не исключает элемент. Эти параметры фильтруют
выдачу; чтение формы и явно сохраняемый снимок остаются полными. Поле `filter` показывает
число элементов до и после отбора, ошибки чтения сохраняются.

По умолчанию `result_mode="changes"`: первое чтение возвращает всю выбранную область,
последующие — только новые и изменившиеся элементы в `elements`, удалённые — в `removed`.
Элемент из `elements` целиком заменяет его предыдущее описание; отсутствие элемента в
этой выдаче не означает его удаления. Текущий фокус, ввод, страницы и прочий контекст
возвращаются целиком. При `include_tables=True` в `table_rows` попадают только изменившиеся
таблицы, каждое описание заменяет прежнее. `changed=false` означает отсутствие изменений.
`result_mode="full"` запрашивает полное описание и обновляет точку сравнения.

Поле ответа `result_mode` указывает фактический режим. Смена фильтров, повторное открытие
формы, потеря снимка или ссылок возвращают полное описание с `full_reason`.
`context_id` — новая автоматическая точка сравнения, `compared_to` — предыдущая.
Неполное чтение возвращается целиком. При нём или невозможности сохранить состояние
`context_id=null` и есть `context_error`; прежняя точка сравнения сохраняется. Строки из `removed` описывают
прежние элементы, их ссылки нельзя использовать для действий.

Хранится одно автоматическое состояние на форму и подключение, в пределах общих
`TC1C_SNAPSHOT_LIMIT` (100) и `TC1C_SNAPSHOT_MEMORY_MB` (128). Оно удаляется после
подтверждённого закрытия окна или отключения; при переполнении вытесняются старые снимки.
`save_as_snapshot=True` создаёт отдельный фиксированный снимок для `compare_snapshot`;
автоматические состояния не входят в `list_snapshots`. Сохранение и сравнение выполняются
по уже прочитанным данным и не добавляют запросов к 1С. Сама форма при каждом вызове
читается заново.

При включении строк таблиц в контекст или снимок проверяется работа массового выделения.
Если таблица требует последовательного обхода, возвращаются `complete=false` и
`table_requires_sequential_read`, без ложного нулевого количества строк. Такие таблицы
читайте отдельно через `read_rows`: переходы по строкам могут менять другие данные формы.

### Дополнительные свойства в `get_context`

Настройка `TC1C_FORM_DETAILS` применяется к MCP и Python API:

- `auto` (по умолчанию) — читать дополнительные свойства, если Testpilot.epf уже подключена;
- `false` — оставить только сведения тестового протокола;
- `true` — читать дополнительные свойства; при запуске клиента через MCP также открыть
  обработку по `TC1C_CODE_EPF`, независимо от разрешений кода и запросов.

В `elements[].details` возвращаются доступные свойства элемента:

| Поле | Свойство 1С |
|---|---|
| `type`, `control_type` | Представление типа элемента формы и его `Вид` |
| `text_edit`, `input_hint` | `РедактированиеТекста`, `ПодсказкаВвода` |
| `type_restriction` | `ОграничениеТипа`: типы, имена объектов метаданных и квалификаторы |
| `choice_mode` | `РежимВыбораИзСписка` |
| `choice_parameters` | `ПараметрыВыбора`: имя и значение каждого параметра |
| `choice_links` | `СвязиПараметровВыбора`: имя параметра и путь к данным |
| `choice_list`, `choice_list_truncated` | Первые 50 элементов `СписокВыбора` со значениями и представлениями; признак наличия остальных |

`type_restriction` описывает именно ограничение элемента, а не тип связанного реквизита:
пустой список означает отсутствие явно заданного ограничения. Список выбора содержит
заданные на форме варианты, а не все записи справочника. Даты и ссылки в значениях
используют тот же формат, что результаты выполнения кода и запросов.

Отсутствующее свойство не подменяется `false` или пустой строкой. Например, у флажка
нет подсказки ввода. Элементы, созданные платформой автоматически, могут не находиться
в коллекции элементов открытой формы; их `details` остаётся `null`.

Все элементы запрашиваются одним обращением к обработке. `form_details.complete` и
`form_details.errors` показывают полноту дополнений. При общем отказе в `form_details`
возвращаются `code` и `error`; основной результат формы сохраняется. Дополнительное
чтение ограничено 30 секундами и более коротким действующим сроком операции.
Во время XML-записи или незавершённого выполнения кода дополнения не читаются.

Обогащение не меняет сохранённые снимки форм и поиск через `find_objects`.

| Действие | Метод 1С | Применим к типам | Параметры |
|---|---|---|---|
| `find_object` | `ТестируемоеПриложение` · НайтиОбъект (`FindObject`) | `ТестируемаяГруппаКомандногоИнтерфейса`, `ТестируемаяГруппаФормы`, `ТестируемаяДекорацияФормы`, `ТестируемаяКнопкаКомандногоИнтерфейса`, `ТестируемаяКнопкаФормы`, `ТестируемаяТаблицаФормы`, `ТестируемаяФорма`, `ТестируемоеДополнениеЭлементаФормы`, `ТестируемоеОкноКлиентскогоПриложения`, `ТестируемоеПолеФормы`, `ТестируемоеПриложение`, `ТестируемыйКомандныйИнтерфейсОкна` | `name=None, cls=None, type=None, root_ref=None, title=None, timeout=0, scope='window'` |

| `wait_for_object_displayed` | `ТестируемоеПриложение` · ОжидатьОтображениеОбъекта (`WaitForObjectDisplayed`) | `ТестируемоеПриложение` | `name=None, cls=None, type=None, title=None, timeout=60` |

Без `limit` поиск возвращает все совпадения. Для листания:

```python
tc_find(action="find_objects", cls="EditField", limit=20)
tc_find(action="find_objects", cursor="…")  # next_cursor из предыдущего ответа.
```

Страница содержит `total`, `returned`, `offset`, `has_more`, `next_cursor`.
`limit` — от 1 до 1000; при продолжении передаётся только курсор и, при необходимости,
`connection_id`. Повторный вызов с тем же курсором читает ту же порцию исходного списка.
Курсор действует до 5 минут в том же подключении, может быть вытеснен новыми поисками.
Просроченный курсор даёт `cursor_unavailable`; нужно начать поиск заново.
Листание не перечитывает 1С, поэтому доступность найденного элемента проверяется при обращении к нему.

## Дополнительные инструменты выполнения

Код, запросы и пользовательские функции включаются независимо. Метаданные по умолчанию
включаются вместе с кодом или запросами; их можно включить и выключить отдельно.
Инструменты функций видны при непустом реестре подключённой обработки. Параметра `action` нет.
Требуется [Testpilot.epf](../onec/Testpilot/README.md), автоматически открываемая при запуске клиента.

| Инструмент | Назначение | Параметры |
|---|---|---|
| `tc_execute_code` | Выполнить BSL; параметры доступны как `Параметры["имя"]`, результат присваивается `Результат` | `code*, context*` (`client`/`server`), `parameters={}, timeout=180, connection_id=None` |
| `tc_execute_query` | Выполнить запрос с параметрами и текущими правами пользователя; вернуть `columns`, `rows`, `returned_rows`, `limit`, `truncated` | `query*, parameters={}, limit=100` (1–500), `timeout=180, connection_id=None` |
| `tc_get_metadata` | Обзор конфигурации, поиск объектов и полей, подробности по полному имени | `name=None, meta_type=None, search=None, field_search=None, sections=None, limit=100` (1–500), `offset=0, timeout=180, connection_id=None` |
| `tc_list_custom_bsl_functions` | Зарегистрированные пользовательские BSL-функции с описанием контекста, параметров и результата | `connection_id=None` |
| `tc_execute_custom_bsl_function` | Вызвать зарегистрированную функцию в указанном при регистрации контексте | `name*, parameters={}, timeout=180, connection_id=None` |

Даты, ссылки и перечисления передаются в [типизированном JSON-представлении](../onec/Testpilot/README.md#типы-значений).

Отдельный инструмент [`tc_run_compatible_scenario`](compatible_scenarios/README.md)
запускает поддерживаемые сценарии Тестера. Параметры:
`path`, `framework='tester'`, `parameters`, `roots`, `timeout=1800`,
`check_only=false`, `application_name=''`, `stop_on_failure=false`,
`result_mode='summary'` (`full` включает шаги каждого теста),
`applications` (имя приложения → каталоги библиотек), `metadata_path` (JSON Тестера
для `Мета` вместо чтения через обработку), `connection_id`.
`path` принимает файл, каталог сценариев или список файлов в порядке выполнения.
Включается настройкой
`TC1C_COMPATIBLE_SCENARIOS`; Testpilot.epf не требуется.
