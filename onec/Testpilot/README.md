# Обработка Testpilot: код, запросы, метаданные и пользовательские функции

`Testpilot.epf` открывается вместе с клиентом тестирования. Обработка содержит два
канала «запрос — результат»: клиентский и серверный. Передача через форматированный
документ позволяет выполнить команду, сохранив активную рабочую форму и её буфер ввода.
Код исполняется в контексте служебной формы, а не в модуле произвольной открытой формы.

## Настройка MCP

```dotenv
TC1C_CODE_EXECUTION=true
TC1C_QUERY_EXECUTION=true
TC1C_METADATA=auto
TC1C_FUNCTIONS=false
TC1C_CODE_EPF=onec/Testpilot/Testpilot.epf
TC1C_CODE_FORBIDDEN_WORDS=
TC1C_CODE_ALLOWED_WORDS=
```

Код, запросы и пользовательские функции включаются независимо. Метаданные в режиме
`auto` включаются вместе с кодом или запросами. Например, при `CODE_EXECUTION=false`,
`QUERY_EXECUTION=true`, `METADATA=auto`, `FUNCTIONS=false` доступны запросы и метаданные.
Обработка запускается, если включена хотя бы одна из её возможностей.
Изменение настроек требует перезапуска MCP-сервера. Агент не меняет их аргументами вызова.

Путь относится к компьютеру запускаемого клиента 1С. Допустим абсолютный путь или
относительный от рабочего каталога процесса. Для отдельной базы профиль запуска
может содержать `code_epf`: относительный путь в нём считается от каталога YAML.
Файл на удалённый компьютер автоматически не копируется.

В Python API методы обработки доступны при её наличии в клиенте 1С,
независимо от настроек публикации MCP.
Для запуска с обработкой укажите `code_epf` в профиле или в `client.launch_client(...)`;
общий путь можно задать через `TC1C_CODE_EPF`. Явный `code_epf=""` запускает клиент
без обработки. Примеры — в [документации Python API](../../docs/PYTHON_TESTING.md#код-и-запросы-в-текущем-сеансе-1с).

При `launch_client` сервер добавляет `/Execute`, подтверждает штатное предупреждение
безопасности только для указанного файла и проверяет версию протокола обработки.
Подготовка входит в общий `wait`. Неудачная подготовка завершает запущенный процесс
и возвращает причину. Права пользователя 1С продолжают действовать: запрет внешних
обработок не обходится. Неизвестный вопрос требует отдельного решения пользователя.

При `connect=false` запуск отвечает после открытия порта с `execution_ready=false`;
подготовка завершается при последующем `connect` к этому запущенному клиенту.
Подключение к чужому уже работающему клиенту использует ранее открытую `Testpilot.epf`.
Если её нет, обычные действия работают, а выполнение возвращает `helper_not_ready`.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| `tc_execute_code` | `code`, `context="client"` или `"server"`, `parameters={}`, `timeout=180`, необязательный `connection_id` | `ok`, `request_id`, `result` либо ошибка |
| `tc_execute_query` | `query`, `parameters={}`, `limit=100` (1–500), `timeout=180`, необязательный `connection_id` | `ok`, `request_id`, `columns`, `rows`, `returned_rows`, `limit`, `truncated` |
| `tc_get_metadata` | `name`, либо `meta_type`, `search`, `field_search`; `sections`, `limit=100`, `offset=0`, `timeout=180`, `connection_id` | Обзор, список или подробности метаданных, `complete`, `errors` |
| `tc_list_custom_bsl_functions` | Необязательный `connection_id` | `functions`: описания зарегистрированных BSL-функций |
| `tc_execute_custom_bsl_function` | `name`, `parameters={}`, `timeout=180`, `connection_id` | `ok`, `request_id`, `result` либо ошибка |

### Метаданные

`TC1C_METADATA=auto` (по умолчанию) публикует `tc_get_metadata`, если включён код
или запросы. `true` включает его независимо, `false` скрывает. При отдельном включении
метаданных сервер тоже автоматически запускает обработку по `TC1C_CODE_EPF`.

Примеры аргументов MCP; в Python — те же аргументы у `client.get_metadata(...)`:

```json
{}
{"meta_type": "Документ", "search": "заказ", "limit": 20, "offset": 0}
{"name": "Документ.ЗаказКлиента"}
{"name": "Документ.ЗаказКлиента.ТабличнаяЧасть.Товары"}
{"name": "Справочник.Номенклатура.СтандартныйРеквизит.Код"}
{"meta_type": "РегистрНакопления", "field_search": "Номенклатура", "limit": 50}
{"name": "Документ.ЗаказКлиента", "sections": ["fields", "table_parts"]}
```

Без фильтров возвращаются имя и версия конфигурации и количество объектов по видам.
`meta_type` выбирается из этого обзора. `search` ищет подстроку в имени или синониме
объекта без учёта регистра, `field_search` — в имени или синониме поля.
Списки отсортированы по имени; `limit` — 1–500, `offset` — смещение, `total` —
число совпадений, `truncated` — есть ли следующая страница.

Для точного `name` возвращаются `object`, `types`, `complete` и `errors`.
`object.fields` содержит однородные строки `name`, `title`, `kind`, `type`, а
`object.table_parts` — табличные части с такими же строками полей. В `types` по
полному имени поля доступны составляющие типа, объекты ссылок и квалификаторы
числа, строки и даты. Для перечислений есть `values`, для основных типов объектов —
`properties`. `sections` ограничивает подробности: `fields`, `table_parts`, `values`,
`properties`. Полное описание одного объекта не обрезается параметрами списка.

Читаются метаданные текущей конфигурации с применёнными расширениями. Виртуальные
таблицы запросов требуют правил языка запросов: их вычисляемые колонки не являются
реквизитами объекта метаданных и отдельно здесь не перечисляются.

Перед сбором метаданных серверный код включает привилегированный режим. Безопасный
режим или профиль безопасности может ограничить его действие; доступные метаданные
всё равно читаются. Исходный режим восстанавливается при успехе и исключении.
Если получить сведения не удалось, возвращается ошибка; частичные описания помечаются
`complete=false` и содержат `errors`. Пагинация сама по себе не делает результат неполным:
наличие следующей страницы обозначается отдельно в `truncated`.

### Пользовательские функции

`TC1C_FUNCTIONS=true` разрешает два инструмента пользовательских BSL-функций.
Они появляются, когда подключена обработка с непустым реестром. В поставляемой EPF
реестр пуст. Регистрация и код пользователя находятся в двух последних областях
модуля, объединённых визуально выделенным блоком. См. [полный пример](CUSTOM_FUNCTIONS.md).

В Python методы доступны независимо от настроек публикации MCP, если клиент
запущен с нужной обработкой. Результаты всех пяти операций проходят через общий
форматтер ответа; при включённом TOON применяется обычное сворачивание.

### Код и запросы

В коде параметры доступны как соответствие `Параметры`; возвращаемое значение нужно
присвоить `Результат`. Пример:

```json
{
  "context": "client",
  "code": "Результат = Параметры[\"текст\"] + \"!\";",
  "parameters": {"текст": "Проверка"}
}
```

Запрос передаётся отдельно от значений параметров:

```json
{
  "query": "ВЫБРАТЬ Код, Наименование ИЗ Справочник.Номенклатура ГДЕ Наименование ПОДОБНО &Имя",
  "parameters": {"Имя": "%чай%"},
  "limit": 100
}
```

Обработчик выполняет запрос или пакет через `Запрос.Выполнить()` и возвращает
результат последней выборки. В пакете можно создавать промежуточные временные
таблицы через `ПОМЕСТИТЬ`, использовать их в последующих запросах и удалять через
`УНИЧТОЖИТЬ`, в том числе после итоговой выборки. Результаты предыдущих выборок
отдельно не возвращаются.

Например, весь этот пакет передаётся одним значением `query`:

```bsl
ВЫБРАТЬ
    &Сумма КАК Сумма
ПОМЕСТИТЬ ВТ_Данные
;

ВЫБРАТЬ
    Сумма * 2 КАК Результат
ИЗ
    ВТ_Данные
;

УНИЧТОЖИТЬ ВТ_Данные
```

При `parameters={"Сумма": 100}` результат содержит строку `{"Результат": 200}`.
Временные таблицы используются в пределах одного вызова.

`РАЗРЕШЕННЫЕ`/`ALLOWED` добавляется, если отсутствует, к первому `ВЫБРАТЬ` каждого
самостоятельного запроса пакета. В последующие части `ОБЪЕДИНИТЬ` оно не добавляется.
Поддерживаются вложенные выборки и `ИТОГИ`; итоговые строки входят в возвращаемые
строки. Синтаксис проверяет платформа 1С.

Параметры передаются в `Запрос.УстановитьПараметр` как данные.
Итоговый результат ограничен 500 строками; ещё одна строка проверяется для `truncated`.
Ограничение числа возвращаемых строк не ограничивает стоимость выполнения самого запроса.
Результат учитывает права пользователя и RLS; пустая выборка не доказывает отсутствие
данных, недоступных этому пользователю.

JSON-ответы преобразуются в TOON общей настройкой сервера. `rows` — список объектов
с одинаковыми ключами колонок. Python API всегда возвращает обычные словари и списки.

## Типы значений

Поддерживаются строки, числа, булевы значения, `null`, массивы и объекты со строковыми
ключами. Даты и ссылки сохраняют тип с помощью явных JSON-объектов:

```json
{
  "Дата": {"$type": "date", "value": "2026-09-21T12:34:56"},
  "Товар": {
    "$type": "ref",
    "metadata": "Справочник.Номенклатура",
    "uuid": "fad620c2-c719-11e4-8ec3-bcaec56cc144"
  },
  "Ставка": {"$type": "enum", "metadata": "Перечисление.СтавкиНДС", "value": "НДС20"}
}
```

Поддерживаются все семейства ссылок 1С:

- справочники, документы, планы видов характеристик, счетов, видов расчёта и обмена,
  бизнес-процессы и задачи — `metadata` и `uuid`;
- перечисления — `metadata` и имя значения в `value`; пустая ссылка имеет `value=""`;
- точки маршрута бизнес-процессов — `metadata` бизнес-процесса и имя точки в `point`;
- таблицы внешних источников и таблицы измерений кубов — `metadata` и `xml`
  со штатным XML-представлением ссылки 1С, сохраняющим тип и значение её ключа.

Полученный объект ссылки можно целиком передать обратно в `parameters`: в коде,
запросе или пользовательской функции он станет исходной ссылкой 1С. Это работает
и для ссылок внутри массивов и объектов, в клиентском и серверном контекстах.
Ответ дополнительно содержит `presentation`; оно не используется для восстановления
ссылки. Для внешней ссылки представление может быть `null`, если его не удалось прочитать.

`NULL` из запросов и `Неопределено` возвращаются как JSON `null`. Входной JSON `null`
преобразуется в `Неопределено`. Дата — дата 1С без часового пояса.
Неподдерживаемый тип даёт ошибку, а не незаметное преобразование в строку.

## Ожидание и доступ к форме

После нажатия кнопки чтение результата ожидает завершения синхронного обработчика
1С. Ответ проверяется по уникальному `request_id`. `timeout` — общий срок вызова,
больше нуля и не более 3600 секунд. Истечение срока не отменяет BSL и не означает,
что код не выполнился. После такого отказа следующий вызов сначала читает старый
результат и возвращает `previous_execution_completed` с `previous_result`;
переданный в этом вызове новый код не запускается. В Python этот ответ можно получить
через `call(..., check=False)` либо `ActionError.result`.

Если срок истёк между кадрами нажатия, следующий вызов сначала отправляет
недостающий завершающий кадр, затем читает результат. Это восстановление применяется
только когда транспорт подтверждает, что кадр ещё не отправлялся.
Если задержался ответ на первый кадр, сначала проверяется этот ответ:
завершающий кадр отправляется только после подтверждённого успеха первого.

Служебная форма скрыта из обычного поиска и обхода. Прямые чтение, запись, нажатие,
закрытие и захват её экрана запрещены общим обработчиком и транспортом, включая
обращения из Python и XML-сценариев. Подключение хранит собственный адрес формы;
после переподключения адрес определяется заново. Закрытие всей 1С разрешено.

Один вызов выполнения образует одну запись журнала действий с параметрами и ответом.
Служебные UI-команды не становятся отдельными шагами журнала. Во время записи
XML-сценария выполнение отклоняется: формат XML не содержит таких шагов. В pytest
вызовы выполнения включаются непосредственно в код теста.

## Запреты в произвольном коде

По умолчанию запрещены идентификаторы:

```text
Удалить, Delete, Записать, Write,
УстановитьПривилегированныйРежим, SetPrivilegedMode,
ПодключитьВнешнююКомпоненту, AttachAddIn,
УстановитьВнешнююКомпоненту, InstallAddIn,
COMОбъект, COMObject,
УстановитьМонопольныйРежим, SetExclusiveMode,
УдалитьФайлы, DeleteFiles, КопироватьФайл, CopyFile,
ПереместитьФайл, MoveFile, СоздатьКаталог, CreateDirectory,
КомандаСистемы, System, ЗапуститьПриложение, RunApp,
НачатьЗапускПриложения, BeginRunningApplication,
ЗапуститьПриложениеАсинх, RunAppAsync
```

`TC1C_CODE_FORBIDDEN_WORDS` дополняет этот список, `TC1C_CODE_ALLOWED_WORDS` задаёт
исключения, например `Записать,Write`. Проверяются целые идентификаторы без учёта
регистра; комментарии и строковые литералы пропускаются. Отказ `forbidden_code`
содержит идентификатор и номер строки, команда в 1С не отправляется.
`Выполнить`, `Execute`, `Вычислить`, `Eval` запрещены всегда, включая вызовы методов
с такими именами. Для запросов используется отдельный инструмент.

Методы запуска программ можно разрешать по отдельности через
`TC1C_CODE_ALLOWED_WORDS`. Например, `ЗапуститьПриложение,RunApp` разрешает
обычный запуск в обоих вариантах языка; остальные способы запуска остаются запрещёнными.

Фильтр не является песочницей: вызванная процедура конфигурации может изменять
данные без перечисленных слов в переданном тексте. Разрешение произвольного BSL
предполагает доверие к исполнителю. Для доступа только к запросам включайте только
`TC1C_QUERY_EXECUTION`.

## Исходники и сборка

Готовая обработка: [Testpilot.epf](Testpilot.epf). Исходники: [src](src).
Требуется управляемое приложение. Обработка использует `ЧтениеJSON`, `ЗаписьJSON`,
`ПрочитатьJSON` и `ЗаписатьJSON`, появившиеся в
[8.3.6.1977](https://wonderland.v8.1c.ru/blog/sredstva-raboty-s-json/).
Работа проверена на 8.3.27.1936 и 8.5.1.1343; совместимость готового EPF
с более ранними версиями пока не проверена.

```powershell
python onec/Testpilot/build.py --exe "C:/Program Files/1cv8/8.3.27.1936/bin/1cv8.exe" --base "D:/Bases/Build"
```

Сборка использует конфигуратор установленной платформы и существующую файловую
базу, сохраняет обработку из XML/BSL; конфигурация базы не изменяется.
