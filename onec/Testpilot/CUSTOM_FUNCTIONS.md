# Пользовательские BSL-функции

В конце [модуля формы](src/Testpilot/Forms/Helper/Ext/Form/Module.bsl) находятся
области `РегистрацияПользовательскихФункций` и `ПользовательскиеФункции`.
При обновлении обработки переносите весь блок между комментариями
«ПОЛЬЗОВАТЕЛЬСКИЕ ДОРАБОТКИ» и «КОНЕЦ ПОЛЬЗОВАТЕЛЬСКИХ ДОРАБОТОК» в новый модуль,
затем пересобирайте EPF. Контексты внутри пользовательской области можно группировать самостоятельно.

В поставляемой обработке реестр пуст. Добавьте описание в `РеестрПользовательскихФункций()`
и реализацию в следующую область. Например:

```bsl
#Область РегистрацияПользовательскихФункций

&НаКлиентеНаСервереБезКонтекста
Функция РеестрПользовательскихФункций()
    Функции = Новый Массив;
    Аргументы = Новый Массив;
    Аргументы.Добавить(ОписаниеПараметраФункции(
        "числа", "array", "Числа, которые нужно сложить", Истина));
    Аргументы.Добавить(ОписаниеПараметраФункции(
        "начальное", "number", "Начальное значение суммы", Ложь, 0));
    ЗарегистрироватьПользовательскуюФункцию(Функции,
        "СложитьЧисла", "Вычисляет сумму переданных чисел",
        "server", "СуммаЧисел", Аргументы, "Число — итоговая сумма");
    Возврат Функции;
КонецФункции

#КонецОбласти

#Область ПользовательскиеФункции

&НаСервере
Функция СуммаЧисел(Аргументы)
    Сумма = Аргументы["начальное"];
    Для Каждого Значение Из Аргументы["числа"] Цикл
        Сумма = Сумма + Значение;
    КонецЦикла;
    Возврат Сумма;
КонецФункции

#КонецОбласти
```

Для клиентской функции укажите контекст `"client"` в регистрации и директиву
`&НаКлиенте` у реализации. Реестр общий для обоих контекстов: он должен только
создавать описания, без обращений к базе и к форме.

Функция-обработчик принимает **один аргумент типа `Соответствие`** со всеми
переданными параметрами. Имя аргумента произвольное; в примере это `Аргументы`.
Это данные вызова функции, а не параметры открытия формы. Ключи соответствия
совпадают с именами параметров в регистрации: `Аргументы["числа"]`,
`Аргументы["начальное"]`. В отдельные аргументы функции эти значения не разворачиваются.
Если входных параметров нет, функция всё равно принимает один аргумент — пустое соответствие.

Функция возвращает значение, поддерживаемое [форматом обмена](README.md).
`Экспорт` для вызова не требуется.

Аргументы `ЗарегистрироватьПользовательскуюФункцию`:

| Аргумент | Назначение |
|---|---|
| `Реестр` | Массив описаний функций |
| `Имя` | Уникальное публичное имя — идентификатор BSL |
| `Описание` | Для чего агенту вызывать функцию |
| `Контекст` | `client` или `server` |
| `Обработчик` | Имя функции в этом модуле |
| `Аргументы` | Массив описаний параметров |
| `ОписаниеРезультата` | Что вернёт функция; необязательная строка |

`ОписаниеПараметраФункции(Имя, Вид="any", Описание="", Обязательный=Ложь,
ЗначениеПоУмолчанию=Неопределено)` создаёт описание одного параметра.
Виды: `string`, `number`, `boolean`, `array`, `object`, `date`, `ref`, `enum`, `any`.
Для дат, ссылок и перечислений используются те же типизированные JSON-значения,
что в `execute_code`. `array` проверяет, что передан массив; типы его элементов
при необходимости проверяет сама функция. Неизвестные параметры и отсутствие
обязательных параметров отклоняются перед вызовом. Значение по умолчанию подставляет сервер.

Сборка:

```powershell
python onec/Testpilot/build.py --exe "C:/Program Files/1cv8/8.3.27.1936/bin/1cv8.exe" --base "D:/Bases/BuildBase"
```

Для MCP задайте путь к своей EPF и `TC1C_FUNCTIONS=true`. После запуска клиента
инструмент `tc_list_custom_bsl_functions` покажет зарегистрированные функции,
а `tc_execute_custom_bsl_function` выполнит выбранную:

```json
{"name": "СложитьЧисла", "parameters": {"числа": [10, 20, 30]}}
```

Результат содержит `ok=true` и `result=60`. Контекст выбирается по регистрации.
Для Python настройки публикации MCP не нужны:

```python
with Client() as client:
    client.launch_client(base="D:/Bases/Demo", code_epf="D:/Tools/Testpilot.epf")
    functions = client.list_custom_bsl_functions()["functions"]
    result = client.execute_custom_bsl_function(
        name="СложитьЧисла", parameters={"числа": [10, 20, 30]}
    )
    assert result["result"] == 60
```

Готовые функции разрешаются независимо от произвольного кода. Фильтр запрещённых
слов проверяет переданный агентом код; исходный код зарегистрированных функций
определяет автор обработки. Функции выполняются с правами текущего пользователя;
получение метаданных не повышает права последующих вызовов.

MCP-инструменты функций видны, пока хотя бы у одного подключённого клиента есть
непустой реестр. `connection_id` выбирает клиент, чьи функции нужны. При изменении
доступности сервер отправляет `notifications/tools/list_changed`. После изменения
исходников пересоберите EPF и перезапустите клиент, чтобы загрузить новую версию.
